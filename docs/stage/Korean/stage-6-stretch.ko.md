## 공통 준비 (한 번만, 약 2~3시간)

### S.1 카메라 설치

```
              [카메라] 책상 위 50~60cm, 수직으로 내려다봄
                  │
   ┌──────────────┴──────────────┐
   │ M1                       M2 │   M1~M4: 가리키기 영역
   │       가리키기 영역         │          네 모서리의 ArUco 마커
   │    (블록을 놓는 곳)         │
   │ M3                       M4 │
   └─────────────────────────────┘
              로봇 베이스
```

- 클램프나 삼각대로 고정하고, 보정 후에는 카메라를 움직이지 않습니다. 밝은 단색 책상면, 고른 조명.
- 영상용으로 두 번째 휴대폰을 삼각대에 놓고 로봇 정면을 촬영합니다 (소프트웨어와 연결하지 않음).

### S.2 가리키기 영역 · `src/demo/workspace.py`

- 관절 자세를 샘플링해 FK로 계산하고, 책상 위 120mm와 60mm 모두에서 위치 전용 IK가 성공하는 책상 위 점만 남깁니다.
- 로봇 앞쪽에서 그런 점들로 이루어진 가장 큰 직사각형을 고르고, `runs/point/area.json`에 저장합니다 (베이스 기준 모서리 좌표).
- 마커 4개를 인쇄해 모서리에 붙이고, 베이스 기준 위치를 자로 잽니다 (±2mm). `config/camera.local.yaml`에 저장.

### S.3 보정 · `src/demo/calib.py`

- 마커 감지(OpenCV ArUco) → 이미지에서 책상 평면(베이스 좌표, mm)으로의 호모그래피.
- 카메라 내부 파라미터: OpenCV 체커보드 보정 (약 30분, 15~20장 촬영). 이어서 마커로 `solvePnP` → **베이스 기준 카메라 자세**. `config/camera.local.yaml`에 저장하고, B의 MuJoCo 카메라에 그대로 사용.
- 확인: 잰 위치 5곳에 블록을 놓았을 때 호모그래피 오차 10mm 이하.

### S.4 가리키기 동작 · `src/demo/point.py`

`point_at(xy_mm)`: 대기 → 경유점(xy, 120mm) → 가리키기 자세(xy, 60mm) → 1초 유지 → 대기. 사전 점검: 모든 경유점에서 IK 성공, 관절 변화 5° 미만, 가리키기 영역 안.

## A. 실물 가리키기 (Spark + SAM 3.1)

### A.1 흐름 · `src/demo/point_physical.py`

```
명령 ("파란색 어딨어?" / "Where is the blue one?")
  → Spark: {"colour": "blue"} (구조화된 출력)
카메라 프레임
  → SAM 3.1 텍스트 지정 분할: "blue LEGO brick" → 마스크 → 중심점(픽셀)
  → 호모그래피 → 책상 xy (mm)
  → 마스크와 목표 표시가 그려진 화면을 보여주고, 사람이 Enter
  → point_at(xy)
```

- Spark: `muse-spark-1.3-contributor`, 출력 형식 `{"colour": "red"|"blue"|"green"|"yellow"|"unknown"}`. `unknown`이면 다시 묻습니다.
- SAM 3.1: Model API 사용 (요청 형식은 `docs/sam/segmenting` 확인). 마스크가 여러 개면 점수가 가장 높은 것, 없으면 "찾지 못함" 보고.
- 시차: 위에서 내려다보는 카메라라 블록 윗면의 마스크 중심을 써도 오차가 수 mm 수준입니다. S.3 확인에서 문제가 없으면 무시합니다.

### A.2 명령어

```bash
python -m src.demo.workspace --plan
python -m src.demo.calib
python -m src.demo.point_physical      # 명령 입력 → 확인 → 가리키기
```

### A 완료 기준

- [ ] 20회 시행 (색마다 5회, 무작위 배치): 18회 이상 성공.
- [ ] 명령이 화면에 보이는 시행 영상 최소 3개.

## B. 시뮬레이션 VLA 가리키기

### B.1 장면 · `src/vla/scene.py`

| 요소 | 설정 |
|---|---|
| 로봇 | `models/robot_inferred.xml` (기본 도형만) |
| 책상 | 평면. 가리키기 영역은 S.2 결과 사용 |
| 블록 | 32 × 16 × 11mm 상자, 빨강·파랑·초록·노랑, 장면마다 3~4개, 서로 80mm 이상, 회전 무작위 |
| 카메라 | **실물 카메라와 같은 자세와 화각** (`config/camera.local.yaml`). 256 × 256 RGB 렌더 |
| 상태 | 관절 위치 6개 |
| 행동 | 관절 목표 각도 6개 (절대값), 10Hz |
| 도메인 랜덤화 | 블록 색조 ±8%, 밝기 ±20%, 책상 색(흰색·밝은 회색·베이지), 조명 방향, 카메라 자세 ±2cm / ±3°, 이미지 노이즈와 약한 흐림 |

### B.2 명령 (영어 템플릿)

"Point to the {colour} block." · "Where is the {colour} one?" · "Show me the {colour} brick." 목표 색은 에피소드 전체에서 균형을 맞춥니다.

### B.3 에피소드 (5초 = 50스텝)

| 구간 | 시간 |
|---|---|
| 대기 (팔이 화면 밖) | 0.5초 |
| 경유점을 거쳐 가리키기 자세로 이동 | 3초 |
| 유지 | 1초 |
| 대기 자세 쪽으로 복귀 | 0.5초 |

전문가 시연 = 실제 블록 위치로 S.4의 `point_at` 실행.

### B.4 데이터 · `src/vla/generate.py`

- 에피소드 400개 (목표 색마다 100개). 학습 360 / 검증 40.
- LeRobot 데이터셋 형식 (작성 API는 최신 문서 확인). 로컬 `runs/vla/dataset/` → Modal Volume.

### B.5 사전 점검 (실패하면 중단)

- 첫 프레임: 모든 블록이 보이고, 팔은 보이지 않음.
- 목표 색 비율이 각각 23~27%.
- 모든 에피소드에서 IK 성공, 관절 범위 위반 없음.
- 첫 프레임 3 × 3 격자를 저장해 사람이 한 번 확인.

### B.6 Modal 학습 · `src/vla/train_modal.py`

| 설정 | 값 |
|---|---|
| 기본 모델 | 공개 SmolVLA 기본 체크포인트 |
| GPU | A100 40GB |
| 스텝 | 10,000 (검증 손실이 더 줄지 않으면 조기 종료) |
| 배치 | 32 |
| 체크포인트 | 2,000스텝마다 Modal Volume에 저장 |
| **타임아웃** | **4시간** |
| 실행 | 분리 실행, 무인 |

먼저 최신 LeRobot 학습 명령과 SmolVLA 설정 이름을 확인합니다.

### B.7 평가 · `src/vla/eval.py`

- 새 장면 100개. 두 가지 방식으로 평가:
  - **폐루프:** 동작 묶음마다 정책을 다시 호출.
  - **첫 프레임만:** 첫 프레임에서 한 번만 호출하고 동작 묶음 전체를 실행 (B2에서 쓰는 방식).
- 지표: 성공률, **다른 블록을 가리킨 비율**, 평균 수평 오차. 무작위 수준은 약 25~33%.
- 최종 영상용 2 × 3 영상 격자 저장.

## B2. 시뮬레이션 → 실물 이식

### B2.1 맥에서 추론 · `src/vla/run_real.py`

1. 첫 프레임 촬영 (팔은 대기 자세, 화면 밖) → 256 × 256으로 크기 변경.
2. 명령과 함께 정책을 한 번 실행 (MPS 또는 CPU) → 동작 묶음.
3. **동작 묶음 안전 점검:** 관절 범위, 스텝당 변화 5° 미만, 최종 끝단 위치가 가리키기 영역 안이고 책상 위 40mm 이상. 어긋나면 거부.
4. 예측된 목표를 화면에 표시하고, 사람이 Enter.
5. 가드가 켜진 상태에서 `move_joints`로 10Hz 실행.

### B2.2 실물 평가

- 20회 시행 (색마다 5회), 무작위 배치.
- 성공 여부 자동 측정: 엔코더로 계산한 끝단 xy(FK)와 SAM 3.1 + 호모그래피로 찾은 블록 중심 비교.
- 시뮬레이션과 실물 성공률을 나란히 보고.

### B2.3 선택: 실물 데이터로 소량 파인튜닝

- 실물 에피소드 30개를 **자동으로** 수집: 사람이 블록을 놓고, A의 흐름(Spark + SAM + IK)이 전문가 역할을 하는 동안 카메라와 엔코더를 기록.
- 시뮬레이션 400개 + 실물 30개로 파인튜닝 (Modal, 약 1시간). B2.2를 다시 실행.

### B2 완료 기준

- [ ] 실물 20회 시행 완료, 성공률 보고 (값과 무관).
- [ ] 시행 영상 최소 2개. 실패가 있다면 실패 장면도 포함 (정직한 결과).
