# 개발 계획: 업데이트 v2

**날짜:** 2026년 10월 29일 (Day 3) · **기준:** `PLAN.md` (v1으로 그대로 유지)

이 업데이트는 (1) 5단계와 6단계 사이에 세 단계를 끼워 넣고, (2) 제어를 PC나 모바일 기기에서 단독으로 실행할 수 있도록 **컨트롤러 패키지**를 정의합니다. 이 문서에 따로 적지 않은 내용은 모두 `PLAN.md`를 따르고, 두 문서가 다르면 **v2를 따릅니다.**

## 1. 업데이트 이유

- 5단계 시뮬레이션 작업(코드 생성, 리허설, Blender 자세 검증)은 성공했지만, **관절 범위를 추론하지 않아** 무작위 자세 10개가 모두 자기 충돌.
- 실물 쪽은 실행하지 않음: 브로커 없음, 브릭 연결 안 됨, 원점 복귀 방향 미확인.
- 6단계 A와 B2는 안전하게 동작하는 실물 로봇을 전제로 함. 5단계와 6단계 사이에 전용 단계가 빠져 있었음.
- 브로커와 제어 로직이 모두 PC에 묶여 있어서 패드–로봇 구성을 하려면 서버를 새로 만들어야 했음. PC와 모바일은 실행 환경이 달라서(모바일은 Python 서비스, 별도 브로커 프로그램, 백그라운드 서버를 PC처럼 실행할 수 없음) 제어 쪽을 처음부터 플랫폼 무관 부분과 플랫폼별 부분으로 나눠야 함.

### 단계별 담당 범위

- **5A (시뮬레이션만):** 형상으로 구한 센서 경계, 충돌 경계, 관절 간 제약(예: J2–J3), IK와 생성 코드에 적용, `poses10_safe.json`. 범위와 관절 간 제약은 **로봇 패키지** 항목(5절)으로 출력.
- **5B (하드웨어만):** **허브 기기**의 MQTT 브로커, 마스터 Wi-Fi + 슬레이브 블루투스, 로봇을 모르는 브릭 프로그램, 브릭 내 가드(센서, 원점 복귀, 정지 감지, 모터 각도 제한, 하트비트, 블루투스), PC 드라이버, 연결과 시간 확인. 브릭은 설정 가능한 허브 주소로 접속하고, MQTT 계정은 `hub`.
- **5C (컨트롤러 패키지 + 실물 검증):** 4계층(5절)으로 만든 컨트롤러 패키지, 로컬 웹 화면(Streamlit 없음), 마법사(원점 복귀, 방향 확인, 실제 센서로 경계 측정, 안전 자세 재현, 직교 좌표 시험), 보고서와 나란히 놓은 이미지, 적합성 시험 세트 출력.

## 5. 컨트롤러 패키지 (PC 또는 모바일, 단독 구성)

제어에 필요한 모든 것(브로커, 제어 로직, 화면)을 **한 기기**(PC 또는 iPad·휴대폰)에서 동작하도록 묶어, **PC–로봇** 또는 **패드–로봇** 단독 구성을 가능하게 합니다.

```
┌──────────────────────────────────────────────┐
│ ④ UI (HTML/JS)                                │ PC: 브라우저 · 모바일: 앱 안의 WebView
├──────────────────────────────────────────────┤
│ ② 코어 로직 (플랫폼 무관)                        │ FK/IK, 범위, 관절 간 제약, 경로 검사,
│                                               │ 동기 이동, 원점 복귀 순서,
│                                               │ 마법사 상태 흐름, 프로토콜 변환
├──────────────────────────────────────────────┤
│ ③ 어댑터 (플랫폼별)                              │ Transport · Storage · Lifecycle
├──────────────────────────────────────────────┤
│ ① 로봇 패키지 (데이터, JSON)                      │ 기구학 모델, 범위, 관절 간 제약,
│                                               │ 포트 배선, 오프셋, 안전 자세
└──────────────────────────────────────────────┘
            ↕ MQTT (모든 플랫폼에서 같은 토픽과 메시지)
   EV3 브릭: 기기 종류를 모름, 최종 안전 판단은 브릭에서
```

- **허브**는 컨트롤러 패키지를 실행하는 단 하나의 기기로, 브로커를 띄우고 조작 권한을 가집니다. 한 세션에 허브는 하나입니다.
- PC 전용 **저작 도구**(추론 에이전트, Blender, MuJoCo, 코드 생성, BVH 충돌 분석)는 따로 둡니다. 이 도구들의 결과물이 로봇 패키지입니다.

### ① 로봇 패키지

- 버전이 붙은 JSON 묶음 하나(`robot_package.json` + 형식 버전). 저작 도구가 생성.
- 실행에 필요한 것만 담음: 추상 기구학, `limits_deg`, `coupled_limits`, 모터·센서 포트 배선, 원점 복귀 설정, 영점 오프셋, 안전 자세, 속도 상한.
- 메시와 부품 데이터가 없어서 모바일에서도 가볍고, 공개 정책(PLAN v1 4a절)과도 맞음. 패키지 내용 제약과 검증기는 5A단계에 정의.
- **비공개 시각 팩:** 개발, 테스트, 데모 영상용으로 링크별 실제 레고 메시를 둠 (`assets/private/visual_pack/`, git 제외). 콘솔에서는 `--private-visuals` 옵션일 때만 표시하고, `src.release.check`로 모든 배포에서 제외.
- 실행 중 충돌 안전은 메시 검사가 아니라 **5A에서 미리 계산한 범위와 부등식**으로 판단.

### ② 코어 로직

- 순수 계산과 상태 흐름만. **파일, 네트워크, OS를 직접 호출하지 않음.** 모든 입출력은 어댑터를 거침.
- 해커톤 구현: Python (PC).
- **적합성 시험 세트:** Python 코어가 정답 사례를 JSON으로 내보냄 (FK/IK 입출력, 범위·경로 판정, 프로토콜 메시지, 마법사 상태 전이, 안전 거부 사례). 이후의 다른 구현(예: 모바일)은 이 사례를 모두 통과해야 함. 이것이 이식의 기준.

### ③ 어댑터

| 어댑터 | PC (해커톤) | 모바일 (로드맵) |
|---|---|---|
| Transport | PC의 외부 Mosquitto | 앱에 내장한 브로커 |
| Storage | 파일 시스템 (`config/`, `runs/`) | 앱 저장 공간 |
| Lifecycle | 일반 프로세스 | 백그라운드 전환이나 화면 잠금으로 하트비트가 멈춤 → 브릭이 로봇을 정지 |

### ④ UI

- 일반 HTML/JS, 모든 자원 로컬. 같은 화면 코드가 PC 브라우저와 모바일 WebView에서 동작.
- 비상 정지 버튼 항상 표시, 누르고 있는 동안만 움직이는 조그, 터치하기 쉬운 배치.

### 브릭 쪽 (프로토콜은 그대로)

- 브릭은 설정 가능한 **허브 주소**(고정 IP 또는 로컬 이름 `.local`)로 접속.
- MQTT 계정 `hub`. 토픽 권한 규칙은 5B와 동일.
- 허브 종류와 상관없이 안전 장치는 브릭에 유지: 센서 가드, 모터 각도 제한, 하트비트 워치독(모바일 백그라운드 전환에도 대응), 블루투스 워치독, 잠금.

### 범위

| 항목 | 해커톤 | 로드맵 |
|---|---|---|
| PC–로봇 컨트롤러 패키지 (Python 코어 + Mosquitto + 웹 화면) | ✅ | |
| 4계층 분리와 로봇 패키지 형식 | ✅ 처음부터 적용 | |
| Python 코어에서 적합성 시험 세트 생성 | ✅ | 모바일 코어 검증에 사용 |
| 브릭의 허브 주소 설정과 `hub` 계정 | ✅ | |
| 패드–로봇 컨트롤러 패키지 (앱 껍데기, 내장 브로커, 코어 재구현) | 설계 메모만 | ✅ |

## 6. 갱신된 규칙

- 선택 A(실물 가리키기)는 **5C 이후**, Day 9 전까지 2일 이상 남았을 때 시작.
- 선택 B(시뮬레이션 VLA)는 **5A 이후**, 3일 이상 남았을 때 시작 가능. 하드웨어 불필요.
- 선택 B2(시뮬레이션 → 실물)는 A, B, 5C 완료 후 1일 이상 남았을 때.
- **5B를 통과하기 전에는 5C의 실물 작업을 시작할 수 없음.** Day 4가 끝날 때까지 5B가 안 되면 다른 작업을 멈추고 연결부터 해결.
- 7단계는 5C 콘솔을 `sim` 모드로 써서 절차적 생성 로봇을 불러올 수 있음.
- **`AGENTS.md`에 추가할 규칙:** 코어 로직은 파일, 네트워크, OS를 직접 호출하지 않고 어댑터를 거친다. 저작 도구에서 실행 환경으로 넘어가는 입력은 로봇 패키지 하나뿐이다.

## 7. 갱신된 대안

- 5A 관절 간 제약이 너무 보수적이면 → 격자 조회표.
- 5B MQTT가 불안정하면 → 같은 메시지를 TCP로. 블루투스가 불안정하면 → 슬레이브도 Wi-Fi로.
- 5C 화면이 늦어지면 → 같은 마법사를 CLI로 실행하고 화면은 나중에.
- 5C에서 측정 센서 경계와 시뮬레이션 경계가 10° 넘게 다르면 → 측정값으로 동작, 해당 관절 표시, 2.7단계 재확인.
- 계층 분리 때문에 5C가 늦어지면 → 로봇 패키지 형식과 적합성 시험 세트 출력은 유지하고, 어댑터는 PC 구현만 단순하게 둠.
