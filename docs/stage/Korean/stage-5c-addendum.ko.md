# 5C단계 추가 문서: 5B 이월 작업과 축소 범위

**상태: 추가 문서.** `stage-5c-control-console.ko.md`는 그대로 두고, 이 문서가 우선합니다. 5C 세션은 이 문서부터 읽습니다.

## 1. 기존 문서와 달라진 결정

| 항목 | 기존 문서 | 현재 결정 |
|---|---|---|
| 브릭 플랫폼 | ev3dev2 (5B 문서) | **Pybricks MicroPython** (`src/ev3/brick_mp/`) |
| MQTT | 계정 + ACL | **미인증**, 브로커는 허브 LAN IP에만 연결 |
| 콘솔 | 4계층 + three.js UI + 모바일 | **미니 콘솔(`src/console/mini.py`) + 단계별 마법사 우선** |
| 연기 | – | three.js 3D UI, 시뮬레이션 일치 검사(sim parity), conformance 테스트, 모바일 노트, `src/core` 분리 |

연기한 항목은 M1~M7이 모두 끝나고 시간이 남을 때만 진행합니다.

## 2. 현재 상태

- **있음:** 패키지 로더·빌더(`src/package`, `src/codegen`), `robot_package.json`, 관절 ↔ 모터 변환(`src/kin`), 미니 콘솔, 호밍 API(`/api/home`, 센서 규칙을 먼저 설정하도록 수정됨). 테스트 293개 통과.
- **없음:** 방향 확인, 범위 측정, 자세 재현 마법사, 보고서.

| 순서 | 작업 | 담당 | 완료 기준 |

### M1 실물 측정 항목

| 항목 | 통과 기준 |
|---|---|
| 모든 모터 조그 ±3° (관절 기준) | 정지 감지로 끊기지 않고 움직임. 끊기면 정지 감지 기준과 속도 확인 |
| 센서 5개 | 누를 때마다 해당 포트 이벤트 표시 |
| 양쪽 브릭 간 지연 | 오른쪽 센서 → PC 표시 1초 이내 |
| E-STOP | 양쪽 브릭 정지, 정지까지 걸린 시간 기록 |
| 하트비트 | 콘솔 종료 후 2초 안에 정지 |
| 블루투스 끊김 | 오른쪽 전원 끄면 왼쪽도 정지 |
| 범위 거부 | 범위 밖 목표를 보내면 거부 |
| 오프라인 | 인터넷 선을 빼도 위 항목 동작 |

## 4. 마법사 공통 규칙

- **로봇 패키지 기반:** 관절 이름, 포트, 기어비, 범위는 모두 로봇 패키지에서 읽습니다. MR JOS 전용 값은 코드에 넣지 않습니다. 같은 마법사를 5D 생성 로봇에도 그대로 씁니다.
- **관절 각도 기준:** 화면 입력은 관절 각도로 받고, 화면에는 관절 각도와 모터 각도를 함께 표시합니다. 변환은 PC 쪽에서 합니다.
- **처음 움직일 때:** 관절 기준 ±5° 이내, 낮은 속도로 움직이고, 사람이 손으로 받칩니다.
- **결과 저장:** `runs/stage5c/<날짜>/` (비공개, git 제외)에 JSON으로 저장하고, 짧은 Markdown 요약을 남깁니다.
- **실물 확인 포인트:** 5A에서 남긴 확인 항목을 M5에서 함께 봅니다.
  - D5–D4 접촉이 실제 움직임을 막는지
  - J1 범위([-50°, 39°])가 실제로 이렇게 좁은지

## 5. 마법사별 요점

- **M3 호밍:** 센서 규칙 설정 → 센서 쪽으로 저속(30°/s) 이동 → 센서가 눌리면 정지 → 영점 설정. 정해진 시간 안에 센서가 안 눌리면 정지하고 실패로 보고. 센서가 없는 관절은 정지 감지로 원점을 잡습니다.
- **M4 방향:** 관절마다 +5° 이동 → 사람이 "맞음/반대"를 선택 → 반대면 부호를 설정에 저장하고 다시 확인.
- **M5 범위:** 관절별로 범위 끝 쪽으로 조금씩 이동하고, 사람이 "여기까지"를 선택하면 기록 → 5A 범위와 비교해서 더 좁은 값을 채택.
- **M6 자세 재현:** 5A 안전 자세를 낮은 속도로 하나씩 재현 → 모터 각도 오차 기록 → 보고서 작성.

- 작업마다 시간 제한을 두고, 기준을 못 맞추면 멈추고 보고합니다.
- **외부 연동 규칙:** 실물 하드웨어처럼 이 환경에서 실행할 수 없는 부분은 최소 코드 작성 → 가짜 브릭으로 확인 → 사람이 실행할 명령을 넘기고 멈춤. 실물 결과를 받기 전에는 다시 다듬지 않습니다.

- 단계가 끝나면 `stage5_dev.md`에 요약을 남기고, `LOG.md`에는 한 줄만 씁니다. 커밋은 요청할 때만 합니다.
