## 꼭 확인할 두 가지

**1. 라이선스와 공개 범위**

Rebrickable MOC는 디자이너에게 저작권이 있고, "무료 다운로드"가 공개 라이선스를 뜻하지는 않습니다. 이 모델의 사용 조건을 확인하기 전까지는 **MR JOS와 같은 규칙**을 적용합니다.

- `.io`, 변환한 LDraw, 메시, 렌더는 비공개 (`assets/private/`, git 제외). Modal 업로드 금지.
- 공개 자료(README, 영상)에는 **추상 결과만**: 기본 도형, 관절축, 기어비 표, 지표. 출처(디자이너, MOC 번호)를 표기합니다.
- 디자이너에게 허락을 받으면 렌더도 공개할 수 있습니다. 허락 요청은 사람이 직접 합니다.

**2. 선형 관절 지원 여부**

지금 파이프라인(2~4단계)은 **회전 관절** 중심으로 만들어졌습니다. 갠트리 로봇은 랙과 피니언, 레일 같은 **선형 관절**로 움직일 가능성이 큽니다.

- 먼저 **코드 수정 없이** 그대로 실행해서 결과를 기록합니다. 선형 관절을 인식하지 못하면 그것이 "일반화 실패 사례"입니다.
- 그다음 **선택**으로, 시간 제한 2시간 안에서 선형 관절 지원을 **확장 기능**으로 추가할 수 있습니다. 이 경우 결과를 "코드 수정 없는 일반화"가 아니라 "파이프라인 확장"으로 정직하게 구분해서 보고합니다.

## 회귀 방지 기준 (가장 중요)

7단계의 핵심은 **이미 만든 파이프라인으로 새 모델을 분석하는 것**입니다. 새 모델에 맞추려고 고치다가 MR JOS를 분석하던 능력이 깨지면 7단계는 실패입니다.

**1. 기준선 고정 (작업 전에 한 번)**

- 코드를 건드리기 전에 MR JOS 분석 결과 전체를 **기준선**으로 저장합니다: 링크 분할, 관절 목록·축·위치, 기어비, 연동, 판단 1·2 지표, IK 시험 결과(59/60), GT 비교 결과.
- 저장 위치: `runs/baseline/mrjos_before_stage7/` (비공개, git 제외). 저장소에는 git 태그 `baseline-before-stage7`을 남깁니다.

**2. 허용되는 변경**

| 종류 | 예 | 조건 |
|---|---|---|
| 데이터 추가 | 부품 정보 표에 새 부품 | 항상 허용 |
| 일반적인 버그 수정 | 경계 조건, 파싱 오류 | 레고 구조 일반에 해당하는 이유가 있어야 함 |
| 기능 추가 | 선형 관절 인식 | **기존 회전 관절 로직을 바꾸지 않고 덧붙이는 방식**만 |

**3. 금지되는 변경**

- 특정 모델 전용 처리: `if model == "tbot"`, T-Bot 부품 번호를 코드에 고정 등
- MR JOS 결과를 바꾸는 임계값 조정
- 기존 함수를 통째로 다시 쓰거나 지우기
- 정답(GT)을 추론 경로에 넣기

**4. 변경할 때마다 회귀 검사**

| 항목 | 통과 기준 |
|---|---|
| MR JOS 관절 수, 연동 구조 | 기준선과 **동일** |
| 관절축 방향 / 위치 | 각도 차이 0.5° 이하 / 거리 1mm 이하 |
| 기어비 | 기준선과 동일 |
| 판단 1·2 지표, IK 시험(59/60), GT 비교 | 기준선보다 나빠지지 않음 |
| 기존 테스트 전체 | 모두 통과 |

`scripts/regress_mrjos.sh` 하나로 위 검사를 돌리고, 기준선과의 차이를 표로 출력합니다.

**5. 기준선과 달라지면**

- 바로 멈추고 차이를 보고합니다. 사람이 결정합니다.
- 차이가 개선(GT에 더 가까워짐)이면 이유와 함께 기록하고 기준선을 새로 저장합니다. 개선이 아니면 그 변경은 되돌립니다.

**6. 변경 기록**

변경마다 `stage7_dev.md`에 남깁니다: 무엇을, 왜(어떤 모델에서 드러났는지), 일반 규칙으로서의 근거, 회귀 검사 결과. 변경은 하나씩 따로 커밋해서 쉽게 되돌릴 수 있게 합니다.

## 작업 (시간 제한 3시간, 확장 시 +2시간)

| 단계 | 내용 | 통과 기준 |
|---|---|---|
| T.0 준비 | **MR JOS 기준선 저장, `scripts/regress_mrjos.sh` 작성.** `.io` → LDraw 변환, 비공개 경로에 저장, `git check-ignore` 확인. 사용 조건 메모 | 기준선 저장, 회귀 검사 통과, 비공개 확인 |
| T.1 파싱 | 1단계 파서로 읽고, 부품 정보 표에 없는 부품 추가 (데이터만) | 모르는 부품 목록과 추가 결과 |
| T.2 그대로 실행 | 1~4단계를 **힌트 없이, 코드 수정 없이** 실행 | 결과 표 (링크, 관절 종류·축, 기어비, 연동). 실패하면 실패 지점 기록 |
| T.3 (선택) 선형 관절 확장 | 랙·피니언과 레일을 인식해 선형 관절과 "모터 회전당 이동 거리(mm/회전)"를 계산. 기존 회전 관절 로직에 덧붙이는 방식 | T.2와 결과를 나란히 비교. **MR JOS 회귀 검사 통과** |
| T.4 시각 확인 | 링크별 색칠 렌더(비공개)와 기본 도형 3D 보기에서 관절 이동 | 사람이 보고 판단 |
| T.5 정답 비교 | 사람이 Studio나 설명서로 확인한 관절 3개의 종류와 기어비(또는 mm/회전). **에이전트에 주지 않음** | 비교 표 |
| T.6 보고 | `stage7_dev.md`, README·영상용 추상 결과 표. 마지막 회귀 검사 결과 포함 | 표와 한계, MR JOS 기준선 유지 확인 |
