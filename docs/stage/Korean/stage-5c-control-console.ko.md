# 5C단계: 로봇 제어 프로그램과 웹 콘솔

**Latest:** Day 6 · **필요 조건:** 5A단계(범위, 안전 자세, 로봇 패키지 v0)와 5B단계(하드웨어 연결, 실물 작업용).

**목표:** PC용 **컨트롤러 패키지**(PLAN v2 5절)를 만듭니다. 4계층으로 나뉜 로봇을 모르는 제어 프로그램과, 로봇을 제어하고 검증하는 로컬 웹 콘솔입니다 (실제 센서 확인, 물리 경계 측정, 원점 복귀, 방향 확인, 안전 자세 재현, 정확도 측정). 같은 패키지가 실물 로봇과 MuJoCo 시뮬레이션 모두에서 동작하고, 나중에 로봇 패키지·화면·프로토콜·브릭을 바꾸지 않고 모바일 허브(패드–로봇)로 옮길 수 있는 구조로 만듭니다.

## 설계 원칙

- **허브 하나, 조작 기기 하나:** 컨트롤러 패키지를 실행하는 기기가 허브입니다. 허브가 브로커를 띄우고, 한 세션에서 로봇을 조작하는 유일한 기기입니다.
- **로봇을 모르는 프로그램:** 로봇별 정보는 모두 **로봇 패키지**(`robot_package.json`)에서 가져옵니다. 코드에 관절 이름이나 번호가 없습니다.
- **4계층:** 로봇 패키지(데이터) → 코어 로직(플랫폼 무관) → 어댑터(플랫폼별) → UI(공용 HTML/JS).
- **코어는 직접 입출력하지 않음:** 코어 안에서 파일, 네트워크, OS, MuJoCo, 웹 프레임워크를 호출하지 않고 모두 어댑터를 거칩니다.
- **안전은 UI 아래 두 곳에서:** 코어가 범위, 관절 간 제약, 경로 검사, 속도 상한을 적용하고, 브릭이 모터 각도 제한, 센서 가드, 워치독을 적용합니다. UI는 이를 우회할 수 없습니다.
- **제품이 아니라 도구:** 콘솔은 검증과 데모를 돕는 도구이고, 프로젝트의 핵심은 여전히 추론 → 동작입니다.
- Streamlit 사용 안 함.

## 구조

```
┌──────────────────────────────────────────────┐
│ ④ UI · src/ui/  (HTML/JS + three.js, 로컬 포함) │ PC: 브라우저 · 모바일(이후): WebView
├──────────────────────────────────────────────┤
│   UI 연결부 (PC: FastAPI + WebSocket 껍데기)    │ 모바일(이후): JS ↔ 네이티브 연결
├──────────────────────────────────────────────┤
│ ② 코어 · src/core/  (순수 Python)              │ FK/IK, 범위, 관절 간 제약,
│                                               │ is_path_safe, 동기 이동,
│                                               │ 원점 복귀 순서, 마법사 상태 흐름,
│                                               │ 프로토콜 변환, 안전 검사
├──────────────────────────────────────────────┤
│ ③ 어댑터 · src/adapters/pc/                    │ Transport: MQTT (5B) | Sim (MuJoCo)
│                                               │ Storage: 파일 · Lifecycle: 프로세스
├──────────────────────────────────────────────┤
│ ① 로봇 패키지 · packages/<robot>/               │ robot_package.json (5A에서 생성, 여기서 갱신)
└──────────────────────────────────────────────┘
```

### 어댑터 인터페이스 (`src/core/ports.py`, 추상)

| 인터페이스 | 메서드 | PC 구현 (지금) | 모바일 (로드맵) |
|---|---|---|---|
| `Transport` | `send(brick, cmd)`, `on_state(cb)`, `on_event(cb)`, `estop()`, `heartbeat()` | `mqtt_transport.py` (5B), `sim_transport.py` (MuJoCo) | 앱 내장 브로커 |
| `Storage` | `load_package()`, `save_package(pkg)`, `write_record(session, item)` | `packages/`, `runs/` 아래 파일 | 앱 저장 공간 |
| `Lifecycle` | `on_suspend()`, `on_resume()`, `on_exit()` | 프로세스 시그널 | 앱 백그라운드 전환 / 화면 잠금 |
| `Clock` | `now()`, `sleep(dt)` | 시스템 시간 | 플랫폼 타이머 |

| MQTT | Transport 어댑터가 `hub` 계정(5B)으로 로컬 브로커에 접속. |

## 작업

### 5C.1 로봇 패키지 로더와 코어 (약 3시간) · `src/core/`, `src/package/`

- 로더가 `robot_package.json`을 `docs/robot_package.md` 기준으로 검증 (`schema_version`, `package_version`).
- 빌더가 5A의 패키지 v0에 포트 배선(`config/ports.local.yaml`), 원점 복귀 설정, 오프셋을 합쳐 새 `package_version` 생성.
- 코어 기능: `C`와 포트 배선으로 관절 ↔ 모터 대응, FK/IK, `check_limits`, `check_coupled`, `is_path_safe` (범위 + 부등식만, 실행 중 메시 검사 없음), 동기 이동 계획, 원점 복귀 순서, 프로토콜 변환.
- 코어가 처리하는 명령: `jog(joint, delta)`, `move_joints(q)`, `move_pose(target)`, `home(joint | all)`, `stop`, `clear_latch`. 모든 이동은 안전 검사를 통과해야 하고, 거부되면 이유를 반환.
- 실물 로봇에 연결하면 어떤 이동도 허용하기 전에 패키지의 센서 가드와 모터 각도 제한으로 `set_guards`를 먼저 전송.

### 5C.2 PC 어댑터와 UI 연결부 (약 2시간) · `src/adapters/pc/`, `src/console/`

- `mqtt_transport.py` (5B에서 작성), `sim_transport.py` (패키지로 생성한 기본 도형 MJCF를 쓰는 MuJoCo), `file_storage.py`, `process_lifecycle.py`.
- `src/console/server.py`: `src/ui/`를 제공하고 웹소켓 메시지를 코어로 연결하는 FastAPI 껍데기. 로봇 로직 없음.
- UI로 보내는 상태 스트림 (20Hz): 관절·모터 각도, 센서 상태, 브릭 상태, 잠금 상태, 패키지 버전.

### 5C.3 웹 화면 (약 4시간) · `src/ui/`

| 패널 | 내용 |
|---|---|
| **상태 표시줄** | 백엔드(real/sim), 브릭 온라인 여부, 하트비트, 지연, 잠금 상태, 패키지 버전, **비상 정지 버튼 항상 표시** (PC에서는 스페이스 키도 가능) |
| **3D 보기** | 실시간 관절 각도를 따라 움직이는 로봇. 표시 모드: 로봇 패키지 데이터로 그리는 **기본 도형**(관절 사이 캡슐·원기둥)과 **외곽 상자**(`link_envelopes`), 그리고 **비공개 메시**(비공개 시각 팩의 실제 레고 형상, 개발과 영상 전용, 아래 참고). 범위를 호로, 목표 자세를 반투명으로 표시. 작은 화면용 간단 표시 모드 |
| **관절** | 관절마다 각도, 범위(근거: 센서/충돌/측정), **누르고 있는 동안만** 움직이는 조그 (±1°, ±5°), 안전 최대값으로 제한된 속도 슬라이더 |
| **센서** | 센서별 실시간 상태와 대응 관절 |
| **마법사** | 원점 복귀, 방향 확인, 경계 측정, 자세 재현, 직교 좌표 시험 |
| **로그** | 이벤트, 거부된 명령과 이유, 결과 |

- 처음부터 반응형·터치 친화적으로 만듦 (같은 코드가 모바일 WebView에서도 동작해야 함).
- UI는 연결부 API하고만 통신하고, 기구학이나 안전 로직을 담지 않음.

#### 비공개 메시 모드 (개발, 테스트, 영상용. 배포에서 제외)

전체 검증 전에 동작을 확인하고 데모 영상을 녹화하기 위해 실제 레고 형상을 쓰지만, 배포하지는 않습니다.

| 규칙 | 내용 |
|---|---|
| 출처 | 5A단계의 `assets/private/visual_pack/<robot>/` (git 제외) |
| 켜지는 조건 | 서버를 `--private-visuals`로 시작 **하고** 시각 팩이 있고 **그리고** `manifest.json`이 불러온 패키지 버전과 일치할 때만 |
| 제공 방식 | 별도 경로 `/private/visual/…`, 같은 토큰·`Origin` 확인, `Cache-Control: no-store`. `src/ui/`에 포함하지 않고 오프라인용으로 캐시하지 않음 |
| 기본값 | 꺼짐. UI는 기본 도형을 표시. 시각 팩이 없으면 전환 버튼 자체가 숨겨짐 |
| 겹쳐 보기 검사 | "메시 + 기본 도형" 겹쳐 보기: 움직이는 중 메시와 기본 도형 체인이 어긋나면 패키지나 시각 팩이 틀린 것이므로 콘솔이 해당 링크를 표시 |
| 영상 | 비공개 메시 모드의 화면 녹화는 디자이너 출처 표기와 함께 데모 영상에 사용 가능 (PLAN v1 4a절). 파일 자체는 절대 공개하지 않음 |
| 모바일 | 모바일 앱 배포에는 포함하지 않음. 시험 기기에 직접 복사해 쓰는 것은 로드맵 선택지로만 둠 |

### 5C.4a 배포 보호 검사

- `python -m src.release.check`: `.glb`, `.gltf`, `.obj`, `.stl`, `.io`, `.ldr`, `.mpd`, 로봇 이미지, `visual_pack` 경로가 git 추적 대상이거나, `src/ui/`나 `packages/` 안에 있거나, 배포 압축 파일에 들어 있으면 실패.
- UI 배포용 빌드는 비공개 경로 없이 만듦 (`--private-visuals`가 없으면 경로를 등록하지 않음).
- 테스트와 8단계 제출 전에 실행.

### 5C.4 마법사 (상태 흐름은 코어, 화면은 UI)

**원점 복귀 마법사**
- 관절마다 10% 속도로 원점 복귀 가드 사용. J4는 브릭 간 경로 사용. 감지 → 정지 지연과 넘어간 각도를 보여주고, 넘어간 각도가 5° 여유 이상이면 경고.
- 시뮬레이션 센서 각도(5A.1)와 실물 원점을 나란히 보여주고, 확인 후 영점 오프셋을 로봇 패키지에 기록 (새 `package_version`).

**방향 확인 마법사**
- 관절마다 +15°. 실제 움직임이 3D 보기의 화살표와 같은지 사용자가 확인. 다르면 기록하고 **모델**을 고친 뒤 패키지를 다시 만들라고 안내.

**경계 측정 마법사** (실물 센서 경계)
- 센서 쪽: 5% 속도로 센서를 향해 천천히 이동, 센서가 감지되면 가드가 모터를 멈춤, 그 각도를 `measured`로 기록.
- 반대쪽: 시뮬레이션 충돌 경계 쪽으로 조금씩 조그. 간격이 작아 보이면 사용자가 멈추고 표시. 시뮬레이션 경계를 넘을 수 없음.
- 최종 범위 = 시뮬레이션 값과 측정값 중 더 보수적인 값 − 5° 여유. `limit_source: measured`로 로봇 패키지에 기록.

**자세 재현 마법사**
- 패키지의 안전 자세를 작은 자세부터 30% 속도로 실행. 명령 각도와 엔코더 각도 기록, 해당 렌더(PC에서만, `assets/private/`)를 실시간 3D 보기 옆에 표시, 삼각대 사진 촬영 안내.

**직교 좌표 시험 마법사**
- 5단계 목표 6개 × 3회. 사용자가 자로 잰 값을 입력하면 코어가 오차와 반복 정밀도 계산.

### 5C.5 보고서 · `runs/console/<session>/`

- `report.json` + `report.md`: 원점 복귀 결과와 지연, 방향, 측정 범위 vs 시뮬레이션 범위, 자세 재현 오차, 직교 좌표 정확도, 사용한 패키지 버전.
- 영상용 렌더 | 사진 나란히 놓은 이미지.

### 5C.6 시뮬레이션 동등성과 안전 테스트 · `tests/test_console.py`

- 모든 마법사가 `sim` Transport에서 처음부터 끝까지 실행.
- 안전: 범위 밖 조그, 접힘 목표, 위험한 경로가 이유와 함께 거부. 이동 중 비상 정지가 시뮬레이션을 멈춤. 하트비트가 끊기면 시뮬레이션 정지.
- **정적 검사:** `src/core/`가 `os`, `socket`, `paho`, `mujoco`, `fastapi`, 파일 입출력 모듈을 import하지 않음.

### 5C.7 적합성 시험 세트 · `conformance/`

이후 다른 코어 구현(예: 모바일)의 이식 기준입니다.

- Python 코어가 정답 사례를 JSON으로 내보냄: FK/IK 입출력(허용 오차 포함), 범위·관절 간 제약·경로 판정, 명령별 프로토콜 메시지, 정해진 입력에 대한 마법사 상태 전이, 안전 거부 사례.
- `python -m conformance.run`이 모든 사례를 Python 코어로 다시 실행하고, 100% 통과해야 함.
- 사례는 로봇 패키지와 최소 하나의 절차적 생성 로봇(7단계)에서 만들어, 한 로봇에 묶이지 않게 함.

### 5C.8 모바일 이식 메모 · `docs/mobile_port.md` (설계만)

- `src/ui/`를 그대로 담는 WebView 앱 껍데기, FastAPI 연결부를 대신하는 JS ↔ 네이티브 연결.
- 모바일 Transport로 앱 내장 MQTT 브로커. 토픽, 계정, 권한은 5B와 동일.
- 플랫폼 언어로 코어를 다시 구현하고, 적합성 시험 세트를 통과해야 채택.
- Lifecycle: 앱이 일시 중지되면 `estop`을 보내고 하트비트를 멈춤. 최종 안전장치는 브릭의 워치독.
- 로봇 패키지는 앱 저장 공간에 보관하고, 파일 공유나 로컬망으로 가져옴.

## 실물 실행 순서

1. 허브(PC) 시작: 브로커, 콘솔. `real` 선택 후 가드 설정 확인.
2. 원점 복귀 마법사 (모든 관절).
3. 방향 확인 마법사.
4. 경계 측정 마법사.
5. 자세 재현 마법사 (안전 자세).

## 대안

- 화면 개발이 늦어지면 → 같은 코어 위에서 마법사를 CLI로 실행 (`python -m src.console.cli <wizard>`). 화면은 나중에 마무리.
- 계층 분리 때문에 늦어지면 → 로봇 패키지 형식, 코어·어댑터 경계, 적합성 시험 세트 출력은 유지하고 어댑터는 PC 구현만 둠.
- 측정 센서 경계와 시뮬레이션 경계가 10° 넘게 다르면 → 측정값으로 동작, `LOG.md`에 해당 관절 표시, 2.7단계 대응 재확인.
- 큰 자세가 위험해 보이면 → 작은 자세 5개로 마무리하고 범위를 좁혀 기록.
