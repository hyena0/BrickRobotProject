# 범용화 백로그 (구현하지 않음)

5D 템플릿·드라이버·게이트를 새 부품/새 구조로 넓히기 전에 풀어야 할 문제들.
아래는 이슈 메모이며, 동작 변경은 포함하지 않는다.

## 1. evidence 분리

- 현황: `src/catalog/parts.yaml` 항목이 출처 서술(`evidence`)과 파생값
  (`teeth`, `axis_local`, `holes`, `gear_kind`)을 한 레코드에 섞어 둔다.
  소비 측(`src/tools/geometry.py`, `src/tools/transmission.py`,
  `src/gen/templates.py`)은 측정값과 추론값을 구분하지 못한다.
- 문제: 새 부품 추가 시 파생 규칙이 암묵적이라 검증 불가. 템플릿의
  `_gear_axis_ok` 같은 런타임 단언이 스키마를 대신하고 있다.
- 방향(미정): `observed`(실측/문헌, 출처 필수)와 `derived`(규칙 ID +
  입력 해시) 분리, 파생 규칙의 `--verify` 성격 검사. 카탈로그 스키마
  변경이므로 main과 협의 필요.
- 수용 기준(안): 모든 파생 필드가 규칙 ID로 추적되고, 규칙 위반 항목이
  리포트로 나온다.

## 2. 디퍼렌셜

- 현황: `gear_graph`/`solve_transmission`과 5D 드라이버는 고정축
  기어열의 단일 경로(BFS 1개, 스칼라 부호)만 지원한다.
- 문제: 디퍼렌셜(유성 베벨, 입력 2 → 출력 1)은 2자유도 커플링이라
  단일 경로·단일 부호·전단사 C행렬 가정이 전부 깨진다.
  `ev3_gate.check_coupling`은 커플링을 실패로 판정하므로 디퍼렌셜
  탑재 설계는 현재 게이트를 통과할 수 없다(의도된 loud failure).
- 방향(미정): planetary 노드 타입 + 2입력 전달식, 드라이버 envelope
  확장(커플링 허용 모드), 템플릿/EV3 게이트의 결합행렬 검사 완화.
- 수용 기준(안): 디퍼렌셜 1개 포함 합성 로봇의 비율 행렬이 오라클과
  일치하고, 게이트가 coupling 행을 구분해 리포트한다.

## 3. 링 기어

- 현황: 메쉬 판정·전달식은 외접 기어만 가정한다
  (중심거리 `0.5*(t1+t2)`, 외접 = 부호 반전).
- 문제: 내접(링) 기어는 중심거리 `0.5*(T_ring - T_pinion)`에 부호가
  유지(+)된다. 카탈로그에 ring/internal 구분이 없어 링 기어 부품은
  등록 자체가 불가하고, 템플릿 기어열도 외접 쌍으로만 설계돼 있다.
- 방향(미정): 카탈로그 `gear_kind`에 ring 추가, `check_gear_mesh`의
  내접 판정(동심 + 잇수 차), `_mesh_sign`의 내접 규칙, 템플릿/게이트
  테스트 픽스처.
- 수용 기준(안): 링+피니언 1쌍의 중심거리·비율·부호가 추론과 일치한다.

## 공통 주의

- 세 항목 모두 `src/tools`, `src/catalog` 스키마에 손을 댄다. 5B와
  공유 코드이므로 설계부터 공유 세션에서 합의할 것.
- 구현 전까지는 현재의 loud failure(미지원 구조는 게이트 실패)가
  정상 동작이다. 조용히 통과시키는 방향으로 고치지 않는다.
