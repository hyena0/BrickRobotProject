# Plan Add-on: Generated Robot, Demo Strategy and VLA (draft)

**Date:** Oct 29, 2026 (Day 3) · **Status: draft, not merged.** `PLAN.md` (v1), `PLAN.v2.md` and all existing stage docs stay unchanged. This add-on is merged into them step by step only when the schedule confirms each part (section 8).

## 1. Decisions

1. **First physical demo:** the MR JOS-based robot.
2. **Video:** the MR JOS-based robot is **blurred** in all footage; its inference results are shown only in abstract form.
3. **Hero robot:** a robot **generated by our own generator from our own modules** (Stage 5D).
4. **Virtual first, then physical:** the generated robot is verified virtually (round trip), then **rebuilt physically**.
5. **Control logic for the generated robot:** produced by the same generic pipeline (robot package → controller package, Stages 5A–5C), then **extended to the VLA** (Stage 6B v2, simulation first, then sim → real).
6. **Stretch:** 6A (pointing on MR JOS) is dropped; the pointing task is done by the VLA on the generated robot.
7. **GUI:** 5C GUI reduced to what validation needs; CLI wizards first.

## 2. Why

- The MR JOS design cannot be published; the designer has not replied.
- A generated robot built from in-house modules is fully publishable: modules, LDraw, meshes, renders, physical footage, VLA data.
- Story: read an existing robot (inference) → move it (physical, blurred) → design a new robot (generation) → read it back (round trip) → build it → control it with generated logic → drive it with a VLA.

## 4. Key constraints for the generated robot

| Constraint | Reason |
|---|---|
| **Built only from parts on hand** (`config/inventory.local.yaml`) | It must be rebuilt physically; the generator checks the bill of materials against the inventory |
| **One EV3 brick if possible** (≤ 4 motors, ≤ 4 sensors), e.g., 3–4 joints | Simpler wiring and no Bluetooth relay; the 5B protocol still applies unchanged |
| **Homing sensor per joint where possible** (touch-sensor mounts inside modules) | Safe homing and sensor-based limits (5A/5C) on the new robot |
| **Disassembly order** | Parts come from the MR JOS-based robot (confirmed), so **finish and film all MR JOS physical work (5C) before disassembling it** |
| **Optimal parts use** | Parts = MR JOS robot parts + a limited set of spares. The generator minimises parts and part types within this inventory (section 4a) |

### 4a. Inventory and parts optimisation

- **Inventory source:** the MR JOS robot's parsed part list (exact counts, already available from Stage 1) **plus** a short manual count of spares → `config/inventory.local.yaml` (private, git-ignored). Only the generated robot's own BOM is published.
- **Scarce parts are hard limits:** motors (2 large, 4 medium on the MR JOS robot), touch sensors (4), colour sensor (1), EV3 bricks, turntables, large gears. Spares are added on top.
- **Optimisation order** for the design agent and generator:
  1. Fits the inventory (hard constraint).
  2. Meets the specification (reach, ranges) within tolerance.
  3. Minimum number of distinct part types (faster build, fewer mistakes).
  4. Minimum total part count.
  5. Prefer high-stock parts (beams, pins, axles) over scarce ones.
- **Motor placement guideline:** large motors on the load-bearing joints (shoulder, elbow); medium motors on base yaw and wrist.
- **Irreversibility:** disassembly cannot be undone quickly. Before it: full footage, port map, measurements and the 5C report of the MR JOS robot are saved; the `.io` file stays private so the robot can be rebuilt later.

## 5. Proposed schedule (applies only if adopted)

```
0 → … → 5 (sim) → 5A ─┬→ 5C on MR JOS (physical, filmed, blurred) ─┐
                      └→ 5D design + round trip (virtual) ─────────┴→ 5D physical build
                                                                     → 5A/5C on the generated robot
                                                                     → 6B VLA (sim → real) → 8
5B (parallel) ─────────→ 5C
```

| Day | Work | Gate |
|---|---|---|
| **Day 4** | 5A (MR JOS) · 5B hardware · **inventory** (MR JOS part list + spare count) · module library in Studio using only inventory parts | |
| **Day 5** | 5D generator + round trip (virtual, BOM optimised against inventory) · 5C core + CLI wizards · **start MR JOS physical checks with CLI wizards** | 🔶 Round trip passes and BOM fits? Else hand-assembled module arm |
| **Day 6 (AM)** | Finish 5C physical on MR JOS; **film everything**, save reports and measurements | 🔶 Disassembly checklist complete |
| **Day 6 (PM)** | Disassemble; **build the generated robot** from the step file | |
| **Day 7** | Wiring config + 5A limits + 5C wizards on the **generated robot** (homing, directions, limit capture, safe poses) · 6B data generation + overnight training (sim) | 🔶 Generated robot homes and moves safely? |
| **Day 8** | 6B evaluation in sim · **sim → real on the generated robot** (if Day 7 gate passed) · filming | |
| **Day 9** | Ship, submit by noon ET | |

Tight; every gate is a real cut point. Fallback order if time runs out: (1) skip sim → real, (2) skip VLA training and show the generated robot moving with generated logic, (3) skip the physical build and show the virtual round trip only.
