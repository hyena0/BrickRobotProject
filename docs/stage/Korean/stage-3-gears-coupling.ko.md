# 3단계: 기어와 연동

**Latest:** Day 4 · **목표:** 모터마다 구동하는 관절까지의 기어 경로를 찾고, 기어비와 방향을 계산하며, 관절 간 연동을 하나의 행렬 `C`(`q = C · m`)로 표현합니다.

## 핵심 개념

구동축이 중공 관절(예: 턴테이블)을 통과하면, 모터가 멈춰 있어도 그 관절을 돌리는 순간 축이 다음 링크에 대해 상대적으로 회전합니다. 이것이 **연동**입니다. 각 기어 맞물림은 캐리어 기준 상대 운동 조건(윌리스 방정식)을 따릅니다. 캐리어 링크 L에 달린 기어 a, b에 대해

`T_a · (ω_a − ω_L) = s · T_b · (ω_b − ω_L)`

여기서 `s`는 외접 맞물림이면 −1, 내접이면 +1, 베벨은 형상으로 정해집니다. 맞물림마다 조건을 하나씩 세우고 연립방정식을 풀면 `C`가 정확히 나옵니다.

## 작업

### 3.1 동력 전달 도구 (약 2~3시간) · `src/tools/`

| 도구 | 반환 |
|---|---|
| `gear_graph()` | 노드 = 축 묶음(`trace_axle` 결과), 간선 = 맞물림(`check_gear_mesh` 결과)과 톱니 수, 맞물림 종류 |
| `axle_carrier(axle_group)` | 각 축 묶음이 장착된 링크 (2단계 링크 기준) |
| `solve_transmission(topology)` | 에이전트가 정한 구성(어느 축 묶음이 각 모터의 출력인지, 어느 것이 각 관절의 자식 링크에 고정됐는지, 어떤 맞물림이 실제로 쓰이는지)으로 윌리스 조건을 세워 `C`, 관절별 기어비와 부호, 계수 부족(rank) 문제를 반환 |

풀이기는 정해진 방식의 선형대수입니다. 구성은 에이전트가 정하고, 숫자는 풀이기가 계산합니다.

### 3.2 에이전트 확장

1. `gear_graph`를 호출하고, 모터마다 출력축에서 맞물림을 따라갑니다.
2. 각 경로가 어느 축 묶음에서 끝나는지 정합니다 (관절의 자식 링크에 고정되거나, 관절 자체인 턴테이블을 구동).
3. 쓰이지 않거나 장식용인 기어를 표시합니다 (맞물릴 짝이 없거나, 구조용 랙하고만 맞물림).
4. 특수 기구를 알아봅니다: 디퍼렌셜, 중공 턴테이블을 지나는 축, 피니언 하나가 기어 둘을 구동하는 경우.
5. `solve_transmission`을 호출합니다. 계수가 부족하거나 기어비가 이상하면 구성을 다시 검토합니다.
6. 구동기, 행렬 `C`, 관절별 짧은 설명을 출력합니다. 모터별 브릭과 포트는 `config/ports.local.yaml`(모터 uid → 포트)에서 가져오고, **각 모터가 어느 관절을 구동하는지**는 에이전트가 추론합니다.

참고: 모터 uid → 포트는 사람이 제공한 하드웨어 배선 정보입니다(README에 표시). 모터 → 관절은 추론 대상이며 `wiring_semantic.yaml`로 평가합니다.

### 3.3 평가 · `src/verify/transmission.py`

- 관절별 기어비 오차(%)와 방향 부호를 정답과 비교.
- 전체 `C` 비교: 원소별 최대 절대 차이.
- `LOG.md`에 기록.

## 기준

- 모든 기어비 1% 이내, 모든 부호 일치.
- `C`의 비대각(연동) 항이 정답과 0.02 이내.

## 대안 (Day 4)

직접 기어비는 맞는데 연동이 틀리면, 직접 기어비는 그대로 쓰고 연동 항은 **사람이 제공한 정보**로 README에 명시합니다. 4단계로 진행합니다.
