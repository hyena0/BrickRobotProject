# 9단계: 실기 (IK 제어 + VLA 웹캠 시험)

**상태: 추가 단계.** 실물이 필요한 작업을 한 세션에 모읍니다. 5C·6단계 문서에 남은 실물 항목과, 이전 9단계 초안의 "디지털 트윈" VLA 실기는 이 문서로 대체합니다.

**원칙:** 완벽한 검증이 아니라 **잘 되는 구간 위주**로 진행하고, 성공 장면과 숫자를 확실히 남깁니다. 실패는 짧게 기록하고 넘어갑니다.

**촬영:** MR JOS 디자이너 허락에 따라 실물 로봇은 영상에서 선명하게 촬영합니다. 사진·영상 파일은 저장소에 넣지 않습니다 (`runs/`에만 저장).

| 파트 | 내용 | 실물 브릭 | 우선순위 |
|---|---|---|---|
| A | IK 제어 (콘솔 → 로봇) | 필요 | 1 (포트 문제가 해결되면) |
| **B** | **VLA 웹캠 시험 (판단만)** | **필요 없음** (가짜 브릭) | **1 (오늘 확실히)** |
| C | (선택) 실물 사진으로 미세조정 | 필요 없음 | 3 |
| D | (선택) B의 결과로 실물 로봇 이동 | 필요 | 4 |

## A. IK 제어 실기 (약 60분)

### A.0 포트 끊김 대비 (시작 전)

- 두 브릭 모두 **어댑터 연결** (전압 저하 방지)
- 케이블을 모두 다시 끝까지 꽂기
- 콘솔 안전 규칙에서 **컬러 센서 제외**
- 문제가 생기면 바로 `ssh robot@<브릭 IP> 'dmesg | tail -40'` 결과와 Read state(`latch_reason`, `missing`)를 저장

### A.1 연결과 보정

1. 브로커(`scripts/start_broker.sh`) → 왼쪽 → 오른쪽 브릭 → 콘솔 실물 모드
2. **보정이 끝난 자세에서 시작:** 저장된 보정 불러오기 또는 주차 복원 → 확인 자세에서 화면과 실물 비교. 어긋난 관절만 다시 맞춤

### A.2 IK 동작

- 시뮬레이션에서 오차가 작았던 매트 점부터: 클릭 → 미리보기 → 로봇으로 보내기 → 휴식 자세
- 목표 3~5개 성공. 어긋나는 점은 기록하고 건너뜀
- E-STOP 1회 촬영

**통과 기준:** 매트 점 3개 이상 도달 + 촬영 확보. **포트 문제로 진행이 안 되면 A는 가짜 브릭 촬영본으로 대체하고 B로 넘어갑니다.**

## B. VLA 웹캠 시험 (판단만, 약 2시간)

**목적:** 시뮬레이션에서만 학습한 VLA가 **실제 카메라 영상**에서 얼마나 맞게 판단하는지 측정합니다. 로봇은 가짜 브릭(콘솔 3D 화면)으로만 움직입니다.

**예상:** 가상 이미지 기준 성공률은 41%였습니다. 실제 영상에서는 이보다 낮아 무작위 수준(25~33%)에 가까울 가능성이 큽니다. 낮게 나와도 **시뮬레이션과 실제 사이의 차이를 측정한 결과**로 정직하게 기록합니다.

### B.1 준비물

| 항목 | 내용 |
|---|---|
| 카메라 | USB 웹캠 또는 아이폰(연속성 카메라) |
| 고정 | 삼각대나 스탠드. 받침대 위 50~60cm에서 내려다보게 |
| 받침대 위 | 무늬 없는 밝은 종이 (매트의 글씨·선이 영상에 들어가지 않게) |
| 블록 | 2×4 브릭 빨강·파랑·초록·노랑 (없으면 3색) |
| 체크포인트 | 6,000스텝, 로컬에 내려받은 것, **첫 프레임 방식** |

### B.2 카메라 연결 확인 (10분)

1. 연결된 카메라 목록 확인 (Muse가 만든 명령)
2. 한 장 캡처 → `runs/stage9/webcam/`에 저장되는지 확인
3. macOS에서 터미널·VS Code의 **카메라 권한**이 허용되어 있는지 확인 (시스템 설정 → 개인정보 보호 및 보안 → 카메라)

### B.3 카메라 위치 맞추기 (30분)

1. `config/sim_camera.yaml`의 위치·방향에 맞춰 카메라를 고정
2. **겹쳐 보기 도구**로 실제 사진과 같은 배치의 가상 이미지를 반투명으로 겹침
3. 슬롯 S1~S6 중심의 위치 차이가 **약 1cm 이내**가 될 때까지 카메라를 조정
4. 맞춘 뒤에는 카메라를 건드리지 않음

### B.4 시험 (40분)

배치 하나에 지시 색을 여러 개 시험하면 시간을 줄일 수 있습니다.

1. 블록 3~4개를 슬롯에 놓음 (예: `red=S2, blue=S5, green=S1`)
2. 시험 도구에 배치 입력 → 지시 색 선택 → 실제 사진 캡처 → VLA가 고른 슬롯 기록
3. 같은 배치를 가상 이미지로도 돌려 결과를 함께 기록 (자동)
4. 같은 배치에서 지시 색 3~4개를 시험한 뒤 배치를 바꿈
5. **배치 5~10개, 총 20~30회** 시험

> **정정 2026-11-02 (1회 호출 버그, 결론 철회).** 앞선 세션 기록 "타깃과
> 무관하게 정책이 한 자세로 붕괴" (layout 1에서 1/3)는 정책 판정으로서
> 철회합니다. 당시 시험은 `select_action`을 1번만 호출해 항상 휴식 쪽
> 첫 행동 하나를 읽은 것이고, 진짜 첫 프레임 방식은 큐에 든 50개

### B.5 촬영

화면 녹화 한 장면에 **실제 웹캠 영상 → VLA가 고른 슬롯 → 콘솔 3D 화면의 가리키는 자세**를 함께 담습니다. 성공 1~2개, 실패 1개.

**통과 기준:** 20회 이상 기록 + 실제 사진과 가상 이미지 성공률 비교 표 + 촬영 1개 이상.

## C. (선택) 실물 사진으로 미세조정 (약 2시간, Modal 약 $1~2)

B 결과가 낮고 시간이 남을 때만 합니다.

1. 배치 10~15개를 찍음. 배치마다 지시 색 3~4개를 붙여 **사진 30~50장** 데이터를 만듦. 정답 동작은 슬롯 위치로 IK가 자동 계산 (사람이 정답을 만들지 않음)
2. 기존 가상 데이터 400개와 섞어 Modal에서 짧게 미세조정 (Modal 점검 게이트 통과 후)
3. B.4를 다시 실행해 전후 비교

## D. (선택) 실물 로봇 이동

A의 포트 문제가 해결된 경우에만: B에서 VLA가 고른 유지 자세를 안전 검사 후 저속으로 실물에 보냅니다. 성공 장면 1개를 목표로 합니다.
