# 5D단계: 생성 로봇: 설계, 왕복 검증, 실물 조립

**상태: 추가 초안, 아직 병합하지 않음.** `PLAN.addendum-generated-robot.ko.md`에서 정의합니다. 기존 단계 문서와 `PLAN.v2.ko.md`는 그대로이며, 일정에서 확정될 때만 이 문서를 병합합니다.

**목표:** 원하는 기구학 사양으로부터 직접 만든 관절 모듈을 조합해 새로운 레고 팔을 생성하고, 이를 다시 추론 파이프라인에 넣어 가상으로 검증(왕복 검증)한 뒤 **실물로 다시 조립**합니다. 이 로봇을 **공개용 대표 로봇**으로 삼고, 같은 파이프라인으로 제어 로직을 만든 뒤 VLA(6B v2)로 확장합니다.

**이유:** MR JOS 기반 로봇은 공개할 수 없습니다. 직접 만든 모듈로 생성기가 설계한 로봇은 모델, 메시, 렌더, 실물 영상, VLA 데이터까지 모두 공개할 수 있습니다.

**기존 문서와의 관계:** 7단계의 절차적 생성기 아이디어를 무작위 생성에서 사양 기반 생성으로 확장합니다. 7단계 문서는 그대로 두며, 7단계 생성기는 이 코드를 재사용할 수 있습니다.

## 두 단계로 진행

| 구분 | 작업 | 의존 | 시점 |
|---|---|---|---|
| **1부: 독립 진행** | 5D.0~5D.7 (보유 부품, 모듈, 사양, 설계 에이전트, 생성기, 왕복 검증, 렌더, 조립 자료) | 1~5단계와 5A의 커밋된 코드 (5A 결과는 읽기 전용, 1부에서는 필요 없음) | **5A 커밋 후, 5B와 병행** |
| **2부: 5A 이후** | 5D.8 실물 조립, 5D.9 생성 로봇의 범위·로봇 패키지·제어 로직 | 5A 도구와 패키지 형식 병합, MR JOS 촬영 완료 (Day 6) | Day 6~7 |

**순서:** 5A 완료 → 메인에 5단계와 5A를 함께 커밋 → 그 커밋에서 5B, 5D worktree 생성. 사람이 하는 준비(여분 세기, Studio 모듈 제작, Modal 설정)는 커밋 전에 시작할 수 있습니다.

1부는 `docs/robot_package.md`나 5A의 어떤 결과도 필요하지 않습니다. 정답 기구학은 기존 기구학 형식(`docs/schema.md`)을 씁니다.

### 파일 담당

| 5D가 수정 가능 | 5D는 읽기만 | 5D가 절대 건드리지 않음 |
|---|---|---|
| `src/gen/`, `assets/modules/`, `specs/`, `generated_robots/`, `scripts/heavy_guard.sh`, `src/render/modal_render.py`, `src/catalog/parts_5d.yaml` (추가분), `tests/gen/` | `src/parse/`, `src/catalog/parts.yaml`, `src/tools/`, `src/agent/`, `src/kin/`, `src/verify/`, `src/codegen/`, `src/viz/pose_*.py`, `docs/schema.md` | `src/limits/`, `src/package/`, `src/viz/export_visual_pack.py`, `docs/robot_package.md`, `config/homing*`, `generated/robot_inferred/`, `runs/stage5a/`, 실행 중인 5A 프로세스 |

- **부품 정보 표 추가분:** 모듈에 새로 쓰는 부품은 `src/catalog/parts_5d.yaml`에 넣고, 로더가 `parts.yaml` 다음에 합칩니다. 메인 부품 정보 표와 충돌을 피합니다.
- **Blender MCP:** 5D 세션만 Blender MCP에 연결합니다.

### 로컬 자원 회피 (5A 실행 중)

1. **일괄 렌더는 기본적으로 Modal에서 실행** (5D.6). 로컬은 결과만 내려받음.
2. **로컬 Blender**(LDraw → `.glb` 변환, Blender MCP 확인)는 `scripts/heavy_guard.sh`를 통과했을 때만:
   - 다른 Blender 프로세스 없음 (`pgrep -fl -i blender`),
   - Blender MCP 포트를 다른 프로세스가 쓰지 않음 (`lsof -i :<포트>`),
   - 1분 부하 평균이 CPU 코어 수의 70% 이하 (`uptime`, `sysctl -n hw.ncpu`).
   하나라도 해당하면 5분 기다렸다가 다시 확인하고, 최대 30분이 지나면 작업을 건너뛰고 `LOG.md`에 기록.
3. **로컬은 낮은 우선순위로:** `nice -n 15`, `OMP_NUM_THREADS=2`, Blender `--threads 2`.
4. **5D 내부 순서 지키기:** 5D의 무거운 로컬 작업은 모두 `/tmp/metahack-heavy.lock`을 `flock`으로 잡고 실행. (나중에 5A를 새 세션으로 다시 시작하면 같은 잠금을 쓰게 할 수 있음.)
5. 5A 프로세스나 파일은 **절대** 종료, 일시 정지, 수정하지 않음.

`scripts/heavy_guard.sh` 종료 코드: `0` 사용 가능, `10` 사용 중 (나중에 재시도), `20` 시간 초과 (건너뜀).

### 공유 API 한도

Spark Contributor 한도(분당 150회, 300만 토큰)는 **5A 세션과 공유**합니다.

- 설계 에이전트와 왕복 검증 에이전트는 한 번에 하나만 실행.
- 이 세션의 Muse Code 하위 에이전트는 동시에 최대 2개.
- 429 오류는 지수 백오프로 재시도 (`AGENTS.md`에 이미 있는 규칙).

## 범위 (의도적으로 축소)

- 직렬 팔, **관절 3~4개** (+ 선택 그리퍼), 직선 체인.
- **직접 만든 모듈 3~4개**. 다른 설계에서 패턴을 자동 추출하지 않음.
- **보유 부품만으로 조립 가능**하게, 가능하면 **EV3 브릭 1개** (모터 4개, 센서 4개 이하).
- 가상 검증을 먼저 하고 실물 조립.

## 실물 조립을 위한 제약

| 제약 | 규칙 |
|---|---|
| 보유 부품 | `config/inventory.local.yaml` (비공개) = MR JOS 로봇의 파싱된 부품 목록(1단계의 정확한 개수) + 직접 센 여분. 생성기의 부품 목록이 이 안에 들어가야 함 |
| 최적화 | 1) 보유 부품 안, 2) 허용 오차 안에서 사양 만족, 3) 부품 종류 최소, 4) 부품 개수 최소, 5) 수량 많은 부품 우선 |
| 모터 | 하중을 받는 관절(어깨, 팔꿈치)에 라지 모터, 베이스 회전과 손목에 미디엄 모터 |
| 브릭과 포트 | 가능하면 브릭 1개: 모터 4개, 센서 4개 이하. 포트 배선도 설계 결과에 포함 |
| 원점 복귀 | 가능한 모듈마다 터치 센서 장착부. 센서가 없는 관절은 정지 감지로 원점 복귀 |
| 케이블 길이 | 모터와 센서가 브릭에서 케이블이 닿는 거리 안에 있어야 함 (대략적인 거리 확인) |
| 분해 순서 | 부품을 MR JOS 기반 로봇에서 가져오므로, 그 로봇의 실물 작업(5C)을 모두 끝내고 촬영한 뒤에 분해 |

## 1부 작업 (독립 진행)

### 5D.0 보유 부품 목록 · `config/inventory.local.yaml`

- 1단계 `parts.json`(비공개)에서 MR JOS 로봇의 부품 개수를 스크립트로 뽑고, 직접 센 여분을 더함 (모터, 센서, 턴테이블, 기어, 길이별 빔, 길이별 축, 핀).
- 귀한 부품(모터, 센서, 브릭, 턴테이블, 큰 기어)은 절대 한도로 표시.
- MR JOS 설계의 부품을 담고 있으므로 비공개.

### 5D.1 모듈 라이브러리 (사람이 Studio에서 제작) · `assets/modules/`

모듈은 **보유 부품만으로** 설계하고, 모듈별 설명 파일에 자체 부품 목록을 넣습니다.

| 모듈 | 구성 예 | 관절 |
|---|---|---|
| `M_base_yaw` | 턴테이블 + 피니언 + 모터 장착부 | 회전, 수직축 |
| `M_pitch_worm` | 웜 + 기어 + 모터 (자체 고정) | 회전, 수평축 |
| `M_pitch_direct` | 저감속 스퍼 기어 + 모터 | 회전, 수평축 |
| `M_wrist_roll` (선택) | 작은 기어 단 + 모터 | 회전, 팔 방향 축 |

모듈별 설명 파일(`module.json`): 입력 장착 좌표계, 출력 장착 좌표계, 모듈 좌표계 기준 관절축, 기어비, 모터 종류, **설계 가동 범위**, 센서 장착부, 크기, 부품 목록. 모듈은 본인 저작물이며 저장소 라이선스로 공개.

연결부: 모듈 사이에 3~15구멍 길이의 직선 테크닉 빔 (구멍당 8mm).

### 5D.2 사양 · `specs/<name>.json`

```json
{"joints": ["yaw", "pitch", "pitch", "roll"],
 "link_lengths_mm": [0, 120, 100, 40],
 "ranges_deg": [[-150, 150], [-30, 100], [-120, 120], [-180, 180]],
 "gripper": false}
```

### 5D.3 설계 에이전트 (Spark) · `src/gen/design_agent.py`

- 입력: 사양 + 모듈 설명 파일 + 보유 부품 요약 (개수만).
- Spark가 관절마다 모듈과 빔 길이(8mm 단위로 반올림)를 골라 링크 길이와 범위를 맞추고 이유를 설명.
- 생성기가 조립한 뒤 도달 거리, 반올림 오차, 영점 자세 충돌, 부품 목록 vs 보유 부품을 확인하고, 최적화 점수(부품 종류, 부품 개수, 사용한 귀한 부품)와 함께 결과를 돌려줌. Spark가 수정 (최대 3회).
- 출력: `generated_robots/<name>/robot.ldr` + `expected_kinematics.json` (생성 방식으로 정답을 알 수 있음, `docs/schema.md` 형식) + 설계 범위.

### 5D.4 생성기 · `src/gen/assemble.py`

- 정해진 방식으로 배치: 체인을 따라 모듈 좌표계를 합성하고, 빔을 넣고, 스터드 격자에 맞추고, LDraw로 저장.
- 사전 점검: 영점 자세에서 부품 겹침 없음 (BVH, `heavy_guard` + 잠금 + 낮은 우선순위로 실행).

### 5D.5 왕복 검증 · `src/gen/roundtrip.py`

- `robot.ldr`을 **아무 힌트 없이** 1~5단계(시뮬레이션 부분) 파이프라인에 넣음 (에이전트는 `expected_kinematics.json`을 보지 않음).
- 비교: 관절 수, 축 각도 오차, 축 거리, 기어비, 링크 길이, IK 끝단 오차 (판단 1·2 기준).
- 결과는 `generated_robots/<name>/roundtrip.json`에 저장하고 `LOG.md`에 한 줄 기록.

### 5D.6 시각 자료 (Modal 렌더) · `src/render/modal_render.py`

| 작업 | 위치 |
|---|---|
| 링크별 LDraw → `.glb` 변환 (생성 로봇만) | 로컬, 회피 규칙 적용 |
| Blender MCP 시각 확인 (링크 색칠, 축 표시) | 로컬, 회피 규칙 적용, 5D 세션만 |
| 일괄 렌더: 다방향, 안전 자세, 영상 프레임 | **Modal** |

- Modal 이미지에는 **로컬과 같은 Blender 버전**을 고정해 설치. GPU(L4 또는 A10G급)에서 Cycles 사용.
- 입력: `.glb` 파일 + `render_job.json` (카메라, 해상도, 샘플 수, 자세)을 Modal Volume에 업로드.
- 시점·자세마다 함수 호출 하나, `map`으로 병렬 실행. 호출당 타임아웃 20분. 결과는 `generated_robots/<name>/renders/`로 내려받음.
- Modal로 보내는 것은 생성 로봇 자산뿐. MR JOS 파일은 Mac 밖으로 나가지 않음.
- 예상 비용: Modal $100 중 $2~5.

### 5D.7 조립 자료 · `generated_robots/<name>/`

- `bom.json`: 부품 목록, 보유 부품과 대조.
- `robot_steps.ldr`: 조립 순서대로(모듈 단위) LDraw `STEP` 줄을 넣은 모델.
- `wiring.yaml`: 계획한 모터·센서 → 브릭·포트 배정 (`config/ports.local.yaml`과 같은 형식).

## 2부 작업 (5A 병합 이후)

### 5D.8 실물 조립과 확인 (Day 6 오후)

**분해 전 확인 목록 (MR JOS 로봇을 건드리기 전에):** 5C 실물 실행 전부 촬영, 5C 보고서·포트 배선·측정값 저장, 여러 방향 사진, 나중에 다시 조립할 수 있도록 비공개 `.io` 보관.

1. `robot_steps.ldr`과 `bom.json`으로 조립하고 `wiring.yaml`대로 배선.
2. 조립한 로봇을 렌더와 같은 정면·측면·위 시점으로 촬영.
3. 링크 길이를 자로 재어 모델과 비교 (±3mm), 손으로 관절을 움직여 방향을 모델과 비교.
4. 차이를 `LOG.md`에 기록. 조립 중 모듈이 바뀌었다면 모델을 고치고 왕복 검증을 다시 실행.

### 5D.9 생성 로봇의 범위, 로봇 패키지, 제어 로직

- 모듈의 설계 가동 범위로 초기 범위를 정하고, 5A 도구로 모듈끼리 접히는 충돌(관절 간 제약)을 확인한 뒤 로봇 패키지 생성.
- 새 로봇 패키지 + `wiring.yaml` → 컨트롤러 패키지(5C). 5C 마법사 실행: 원점 복귀, 방향 확인, 경계 측정, 안전 자세 재현, 직교 좌표 시험.
- 이 제어 로직이 VLA(6B v2)의 기반이 됨.

- 부품이 모자라면 → 보유 부품으로 제한해 다시 생성. 그래도 모자라면 가상 로봇으로 유지.
- Modal 렌더에 문제가 생기면 → 밤에 `heavy_guard`를 적용해 로컬에서 줄인 세트만 렌더.
- 실물 조립이 늦어지면 (Day 7 판단) → 6B의 시뮬레이션 → 실물은 생략하고 VLA는 시뮬레이션에서만.
