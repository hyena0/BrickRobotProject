# 2단계: 에이전트 v1, 링크와 관절

**Latest:** Day 3 (판단 1) · **목표:** Spark 에이전트가 파싱된 부품과 기하 도구만으로 로봇을 강체 링크로 나누고, 링크 사이의 관절을 식별합니다.

## 핵심 개념

많은 부품이 링크 안에서 회전하지만 로봇 관절은 아닙니다(기어 축, 아이들러). **로봇 관절**은 베이스에서 끝단까지 이어지는 경로 위에서 두 개의 큰 강체 덩어리 사이에 일어나는 회전입니다. 이 둘을 구분하는 것이 이 단계에서 에이전트의 주된 일입니다.

## 작업

### 2.1 에이전트 루프 (약 2시간) · `src/agent/`

- Responses API, `muse-spark-1.3-contributor`, 1단계 도구로 도구 호출.
- 프롬프트 앞부분 고정: 시스템 프롬프트 → 도구 정의 → 작업. 바뀌는 데이터는 맨 뒤.
- 단계 제한(예: 도구 호출 60회) 후 최종 답변을 강제.
- 최종 답변은 JSON 형식으로 검증(구조화된 출력). 형식이 틀리면 한 번 수정 요청.
- 모든 호출의 `usage`를 `runs/usage.jsonl`에 추가. 전체 기록은 `runs/<id>/trace.jsonl`에 저장(비공개).

### 2.2 에이전트 입력

- 모델 요약: 분류별 부품 수, 모터와 센서 목록과 위치, 전체 경계 상자.
- 넣지 **않는** 것: 하위 모델 이름, 힌트가 되는 색상, `eval/ground_truth/`의 모든 내용.

### 2.3 프롬프트 전략

답이 아니라 방법을 줍니다.

1. 확실히 고정인 연결 종류로만 `rigid_groups`를 실행하고, 묶음을 살펴봅니다.
2. 묶음 사이의 자유 회전 연결마다 로봇 관절, 동력 전달 축, 아이들러 중 무엇인지 판단합니다. 묶음 크기, 큰 덩어리를 싣고 도는지, 끝단 방향으로 경로가 이어지는지를 근거로 씁니다.
3. 실제로는 고정된 묶음(형상 때문에 잠기는 마찰 없는 핀 등)은 합칩니다.
4. 베이스 링크(바닥에 닿거나 브릭을 품은 가장 큰 묶음)와 끝단 링크를 찾습니다.
5. 링크, 관절(축, 위치, 종류), 베이스, 끝단을 출력하고, 관절마다 확신도와 짧은 근거를 붙입니다.

### 2.4 출력

`runs/<id>/links_joints.json` (비공개: 부품 소속 포함)과, 형식에 맞춘 공개용 요약(관절축과 위치만).

### 2.5 평가 · `src/verify/segmentation.py`, `src/verify/joints.py`

- 링크 분할: 예측 링크와 정답 링크를 짝지은 뒤, 올바른 링크에 배정된 부품 비율(부품 수 가중).
- 관절: 개수 일치, 축 각도 오차(°), 예측 축선과 정답 축선 사이 거리(mm).
- `LOG.md`에 짧은 표로 기록.

### 2.6 반복

- 프롬프트·도구 수정은 최대 3회. 한 번에 하나만 바꾸고 결과를 기록합니다.
- 도구가 낸 사실이 틀려서 실패했다면 프롬프트가 아니라 도구를 고칩니다.

### 2.7 센서 대응

- `config/ports.local.yaml`의 센서마다 어느 관절의 원점용인지 에이전트가 추론합니다. 센서가 어느 링크에 붙어 있는지, 어느 관절이 움직일 때 움직이는 부품이 닿거나(터치) 보이게 되는지(컬러)를 근거로 씁니다.
- 센서별 출력: 관절 id, 원점 복귀 방향, 확신도.
- `wiring_semantic.yaml`로 평가합니다. 판단 시점에 틀리면 센서-관절 대응은 사람이 제공한 정보로 바꿉니다.

### 2.8 Blender MCP로 시각 확인 (개발 보조)

- `src/viz/overlay.py`: 예측한 링크별로 부품을 색칠하고, 관절축을 화살표로 그리고, 관절 이름을 표시. Muse Code에서 Blender MCP로 실행하거나 `blender -b`로 백그라운드 실행.
- 에이전트를 실행할 때마다 정면·측면·위 렌더를 `assets/private/renders/<run>/`에 저장. 지표를 보기 전에 사람이 먼저 확인하면 잘못 묶인 링크가 몇 초 만에 보입니다.
- 이 렌더는 영상 소재로도 씁니다 (8단계).

### 2.9 선택 에이전트 도구: `render_view`

- 도구가 주는 사실만으로 관절이 애매하면, Blender로 이미지를 돌려주는 `render_view(방위각, 고도, 확대, 강조할 uid, X-ray)`를 에이전트에게 줍니다.
- 2.1~2.6이 동작한 뒤에만 추가합니다. 이미지 때문에 토큰과 지연이 늘어납니다.

## 판단 1 기준 (첫 실행 전에 확정)

- 링크 분할 정확도: 부품의 90% 이상.
- 관절 개수 정확히 일치.
- 모든 관절에서 축 각도 오차 5° 이하, 축 거리 5mm 이하.

`segmentation.json`의 링크 소속을 **사람이 제공한 입력**으로 주고 README에 명시합니다. 에이전트는 관절축, 기어 트레인, 기구학을 맡습니다.

## 토큰 예상

에이전트 실행 1회: 도구 호출 20~60회, 입력 약 30만~150만 토큰(대부분 캐시) → $0.03~0.15. 개발 합계 $3~8.
