# 개발 계획

Meta Global AI Developer Hackathon (인디 트랙, 1인 참가)
개발 기간: 2026년 10월 26일 ~ 11월 4일. 제출 마감 **11월 4일 오후 9시 ET** (한국 시간 11월 5일 오전 11시). 목표: **11월 4일 정오(ET)까지 제출**.

## 1. 목표

**브릭 단위로 조립만 된 레고 데이터**(부품 번호와 위치·방향만 있고 관절, 리그, 기구학은 정의되지 않음)만 주어졌을 때, **Muse Spark 에이전트**가 로봇의 기구학 체인을 기하학적으로 추론합니다. 추론 대상은 강체 링크, 관절축, 기어 트레인, 기어비, 관절 간 연동입니다. 이어서 정기구학·역기구학(FK/IK)과 실행 가능한 EV3 제어 프로그램을 생성합니다. 생성된 IK로 실물 로봇을 움직이고, VLA 학습용 시연 데이터를 자동으로 만듭니다.

테마: **Push the Frontier**. 사용하는 Meta 모델: Muse Spark 1.3 (Model API), SAM 3.1 (Model API, 선택 A), Muse Code (개발), Muse Spark Open (선택, Baseten).

## 2. 범위

| 등급 | 내용 | 조건 |
|---|---|---|
| **핵심** | 스튜디오 파일 → 기구학 추론 → FK/IK → 검증 → EV3로 실물 로봇 동작 | 필수 |
| **선택 A** | 실물 가리키기: "파란색 어딨어?" → Spark가 색 추출 → SAM 3.1이 블록을 찾음 → 생성된 IK로 그 블록을 가리킴 | 5단계 완료, Day 9 전까지 2일 이상 남음 |
| **선택 B** | VLA 가리키기: 생성된 IK로 MuJoCo에서 시연 자동 생성 → SmolVLA 파인튜닝 → 시뮬레이션 평가 | 4단계 완료, Day 9 전까지 3일 이상 남음 |
| **선택 B2** | B 정책을 실물로 이식 (첫 프레임으로 동작 묶음 1회, 안전 점검 후 실행) | A와 B 완료, Day 9 전까지 1일 이상 남음 |
| 로드맵 | 이미지만으로 추론, 웹캠 오차 보정, 기기 내 모바일 VLA, 교육 키트 | 영상에서 소개만 |

## 3. 파이프라인

```
[입력]  스튜디오 .io 파일 (부품 번호 + 위치·방향만)
   ↓ 파서 + 부품 정보 표
[핵심]  Muse Spark 에이전트 + 기하 도구
        get_parts / find_connections / check_gear_mesh / trace_axle
        → 링크 분할, 관절 위치·축·종류, 기어 트레인, 기어비,
          관절 간 연동, 링크 길이
   ↓
[검증]  정답지 비교 + MuJoCo 정답 모델에서 끝단 오차 측정
        → 실패하면 오차를 에이전트에 돌려줌 (선택: Muse Spark Open 검토자)
   ↓
[생성]  연동 보정이 포함된 FK/IK → EV3 제어 프로그램
   ↓
[실물]  Wi-Fi MQTT → Left 브릭(마스터) ⇄ 블루투스 ⇄ Right 브릭(슬레이브)
        브릭 내 안전 가드 (센서, 정지 감지, 하트비트) → 로봇 동작
[시각]  Blender MCP로 추론된 링크와 축 표시 (개발 중 확인, 영상)
   ↓
[선택 A]  명령 → Spark(색) + 카메라 → SAM 3.1(블록) → 호모그래피 → IK → 가리키기
[선택 B]  생성된 IK → MuJoCo 가리키기 시연 → SmolVLA 학습 → 시뮬레이션 평가
[선택 B2] B 정책을 실물에서 실행 (첫 프레임 → 동작 묶음 1회)
```

### 에이전트 내부 역할 분담

- **도구는 사실을 계산합니다.** 기하 계산, 거리, 축 평행 여부, 같은 축에 꽂힌 부품 등을 정해진 방식으로 구합니다.
- **Spark는 그 사실의 의미를 추론합니다.** 고정 연결인지 회전 연결인지, 어느 기어가 어느 관절을 구동하는지, 중공 턴테이블이나 디퍼렌셜을 통한 연동, 기구학 체인 구성 등을 판단합니다.
- 에이전트는 구조화된 기구학 모델(JSON, 형식은 `docs/schema.md`)을 출력합니다.

## 4. 대상 로봇

- **MR JOS의 6DOF Robotic Arm (Rebrickable MOC-76666)** 기반 6축 로봇 팔. 설명서를 구매해 스튜디오에서 브릭 단위로 재모델링했고, 일부 수정함(그리퍼 추가, PS2 컨트롤러 연결부를 Wi-Fi 구조로 교체).
- 관절 θ1~θ6, 라지 모터 2개 + 미디엄 모터 4개, EV3 브릭 2개(마스터/슬레이브).
- 핵심 난이도: 다단 기어 트레인과 중공 턴테이블을 통한 **θ4 → θ5 → θ6 연동**.
- 디자이너에게 사용 허락 요청함. **대안:** 공개 모델(예: EV3 교육용 Robot Arm H25). 파이프라인은 그대로 사용.

## 4a. 공개 정책

제출 결과물은 로봇 설계가 아니라 **추론한 기구학과 범용 추론 로직**입니다. MR JOS 기반 로봇의 외형은 **데모 영상에만** 출처와 함께 나옵니다.

| 산출물 | 담긴 내용 | 공개 여부 |
|---|---|---|
| 스튜디오 `.io` / LDraw 파일, 렌더 | 외형 + 조립 | 🔴 비공개 (`assets/private/`) |
| 에이전트 로그, 도구 출력, 부품 번호·위치가 담긴 링크 분할 결과 | 조립 (복원 가능) | 🔴 비공개 (`runs/`) |
| 메시가 들어간 정답 MJCF | 외형 | 🔴 비공개 (`eval/ground_truth/`) |
| **추상 기구학 모델** (관절축, DH/링크 치수, 기어비, 연동 행렬, 가동 범위) | 기능적 사실만 | 🟢 공개 |
| 기구학 모델에서 다시 유도한 **폐형해 IK** (예: 구면 손목 분해) | 표준 수학 | 🟢 공개 |
| **학습형 IK** (FK 샘플로 학습한 위치·자세 → 관절각 네트워크, 비전 없음) | 기구학 함수만 | 🟢 공개 |
| **기본 도형 MJCF** (기구학 모델로 만든 캡슐·원기둥) | 기구학만 | 🟢 공개 |
| 생성된 EV3 코드, 모든 파이프라인 코드 | 본인 작업 | 🟢 공개 |
| VLA 데이터셋과 가중치 (선택 B) | **기본 도형 로봇으로만** 학습해야 함 | 🟢 공개 |
| 공개 모델(예: H25) 결과 | 해당 모델 라이선스에 따름 | 🟢 라이선스가 허용하면 공개 |

판단 기준: 로봇을 다시 만들거나 렌더할 수 있게 해주는 정보는 비공개, 어떻게 움직이는지만 설명하는 정보는 공개.

### 단계 전환 규칙

- **일찍 끝나면 바로 다음 단계로.** 남는 날은 선택 목표로 넘어갑니다.
- **늦어지면 "Latest" 날에 대안을 적용**하고 더 끌지 않습니다.
- **선택 목표 진행 여부**는 4·5단계가 끝났을 때 남은 일수로 정합니다.
  - 선택 B는 Day 9 전까지 **3일 이상** 필요 (4단계 직후 시작, 5단계와 병렬 가능)
  - 선택 A는 Day 9 전까지 **2일 이상** 필요 (5단계 이후 시작)
  - 선택 B2는 A와 B 완료 후, Day 9 전까지 **1일 이상** 필요
  - 부족하면 건너뛰고 7단계로 갑니다.
- 오래 걸리는 작업(학습, 일괄 평가)은 백그라운드에서 무인 실행하고, 그동안 다음 단계를 진행합니다.
- 8단계는 진행 상황과 관계없이 항상 하루를 확보합니다.

### 대안

- **판단 1 실패** (링크·관절 식별 불가): 분리 파일의 링크 분할을 입력으로 주고, 관절·기어·IK 추론에 집중합니다.
- **판단 2 실패** (끝단 오차가 큼): 실물은 단순 동작만 보여주고, 기어비·연동 정확도 중심으로 데모를 구성합니다. 선택 A·B는 취소합니다.
- **디자이너 거절** (또는 Day 5까지 회신 없음): 공개 모델로 교체합니다. 파이프라인은 그대로입니다.

## 6. 선택 목표 상세

작업: 책상 위에 색이 다른 레고 블록 3~4개. "파란색 어딨어?" → 팔이 그 블록을 가리킴 (블록 위 60mm에서 멈추고 닿지 않음). 전체 설정은 `docs/stages/stage-6-stretch.md`.

- **공통 준비:** 위에서 내려다보는 고정 카메라, 로봇 베이스 기준 위치를 아는 ArUco 마커 4개 → 호모그래피. 카메라 자세를 한 번 측정해 MuJoCo 카메라에도 그대로 사용. 가리키기 영역은 추론된 작업 공간에서 찾음.
- **A (약 1일):** Spark가 어떤 언어의 명령이든 목표 색을 추출 → SAM 3.1 텍스트 지정 분할로 블록 찾기 → 호모그래피 → IK → 가리키기. 사람이 Enter로 확인. 목표 20회 중 18회 이상 성공.
- **B (약 1.5일):** **기본 도형 로봇**, 실물과 같은 카메라, 도메인 랜덤화가 적용된 MuJoCo 장면. IK로 생성한 에피소드 400개. Modal A100에서 SmolVLA 학습 (타임아웃 4시간). 폐루프와 첫 프레임 전용 두 방식으로 평가.
- **B2 (약 0.5~1일):** 첫 프레임(팔은 화면 밖)으로 B 정책을 한 번 실행해 안전 점검된 동작 묶음을 실물에서 실행. 실물 20회 시행. 선택: A의 흐름을 전문가로 써서 실물 에피소드 30개를 자동 수집해 파인튜닝.
