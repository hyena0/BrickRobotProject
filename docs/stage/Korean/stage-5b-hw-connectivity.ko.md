# 5B단계: 하드웨어 연결 (병행 트랙)

**Latest:** Day 4 · 1~5단계와 **병행 진행** (추론 파이프라인과 의존 관계 없음). 5C단계의 실물 작업 **전에 반드시 완료**.

**기존 문서와의 관계:** 이 단계는 0단계(작업 0.2~0.6)와 5단계(5.3~5.4 실물 실행)에 처음 적었던 하드웨어 항목을 실제 브릭에서 수행하고 검증합니다. 기존 문서는 그대로 두며, PLAN v2부터는 이 단계가 실행 기준입니다.

**목표:** **허브 기기**에서 두 EV3 브릭까지 안정적이고 안전하며 로봇을 모르는 연결. 모든 모터를 명령하고, 모든 센서를 읽고, 모든 안전 정지가 동작해야 합니다. 허브는 컨트롤러 패키지(PLAN v2 5절)를 실행하는 단 하나의 기기로, 해커톤에서는 PC, 이후에는 모바일 기기입니다.

## 연결 구조

```
허브 기기 (지금은 PC, 이후 iPad·휴대폰)
  └─ MQTT 브로커 (허브에서 실행) ── Wi-Fi (로컬망)
                                      │
                      Left 브릭 (마스터) ── 블루투스 ── Right 브릭 (슬레이브)
```

- 마스터가 Wi-Fi로 허브의 브로커에 연결하고, 슬레이브 메시지를 블루투스로 중계합니다.
- 브릭은 **포트만** 압니다. 관절 이름, 기어비, 센서 의미는 모릅니다.
- **브로커 위치에 의존하지 않음:** 브릭은 허브가 어떤 종류의 기기인지 모르고 신경 쓰지 않습니다. 허브를 PC에서 모바일로 옮겨도 브릭 설정의 허브 주소만 바뀌고, 토픽·메시지·브릭 코드는 그대로입니다.
- 로컬망만 사용합니다.

## 로컬 전용 원칙 (외부 서비스 사용 안 함)

하드웨어 경로 전체가 **인터넷이 전혀 없어도** 동작해야 합니다. 이전 레고 로봇 프로젝트와 같은 원칙입니다 (원칙만 따르고 코드는 재사용하지 않음).

| 규칙 | 내용 |
|---|---|
| 브로커는 허브에 | PC(해커톤): PC에 Mosquitto를 설치해 실행. 모바일(로드맵): 앱에 내장한 브로커. **클라우드나 공개 브로커 사용 금지.** |
| 허브 주소 | 브릭은 설정 파일에서 허브 주소를 읽음: 고정 로컬망 IP 또는 로컬 이름 `.local`(mDNS, 로컬망 전용). 클라우드 검색 사용 안 함. |
| 로컬에만 열기 | 수신은 `127.0.0.1`과 허브의 로컬망 IP에서만. |
| 인증 | `allow_anonymous false`, 계정 두 개(**`hub`**, `brick_left`). 비밀번호는 `config/*.local.*`(git 제외)에 보관. |
| 토픽 권한 | `brick_left`: `robot/ack/#`, `robot/state/#`, `robot/event/#`, `robot/status/#` 발행, `robot/cmd/#`, `robot/estop`, `robot/heartbeat` 구독. `hub`: 그 반대. |
| 외부 노출 금지 | 공유기 포트 포워딩 금지. 방화벽은 1883 포트를 로컬망 대역에서만 허용. |
| 외부 호출 금지 | 브릭 프로그램, 드라이버, 확인 도구는 인터넷 요청을 하지 않음. Meta API 호출은 6단계 모듈에서만. |

설정 파일:

- `config/mosquitto.conf.example` (커밋, 비밀 정보 없음): 수신 주소, `allow_anonymous false`, `password_file`, `acl_file`.
- `config/mosquitto.local.conf`, `config/mosquitto.passwd`, `config/mosquitto.acl` (git 제외).
- 브릭 쪽: `hub_address`, 포트, 계정, 비밀번호를 브릭 로컬 설정 파일에 보관 (커밋 안 함).

## 작업

### 5B.1 네트워크와 브로커

- 위의 로컬 전용 설정으로 PC(허브)에 Mosquitto 실행. 허브와 마스터 IP 고정.
- `config/hardware.local.yaml` (git 제외): 브로커 IP, 포트, 계정 이름, 브릭 이름 (`left` = 마스터, `right` = 슬레이브). 비밀번호는 git 제외 파일에서 읽고 코드에 직접 쓰지 않음.
- 확인: `hub` 계정의 `mosquitto_sub`로 마스터의 테스트 메시지를 받음. 익명 접속은 거부됨. 다른 계정으로는 `robot/cmd/#`에 발행할 수 없음.

### 5B.2 프로토콜 · `docs/protocol.md`

| 토픽 | 방향 | QoS | 내용 |
|---|---|---|---|
| `robot/cmd/<brick>` | 허브 → 브릭 | 1 | `{"id", "cmd", "args"}` |
| `robot/ack/<brick>` | 브릭 → 허브 | 1 | `{"id", "ok", "result" \| "error"}` |
| `robot/state/<brick>` | 브릭 → 허브 | 0 | 엔코더(도), 센서 값, 10~20Hz |
| `robot/event/<brick>` | 브릭 → 허브 | 1 | 가드 작동, 정지 감지, 연결 끊김 |
| `robot/estop` | 허브 → 전체 | 1 | 즉시 전체 정지 |
| `robot/heartbeat` | 허브 → 전체 | 0 | 0.5초마다 |
| `robot/status/<brick>` | 브로커 (Last Will) | 1 | `online` / `offline` |

명령: `ping`, `info`, `run_target`, `run_targets`, `read`, `reset`, `stop`, `set_guards`, `clear_latch`.

프로토콜 문서는 플랫폼과 무관하며, 모든 허브 구현(지금은 PC, 이후 모바일)이 따라야 하는 약속입니다.

### 5B.3 브릭 프로그램 · `src/ev3/brick/`

- `master.py` (허브로의 MQTT 클라이언트 + 블루투스 중계), `slave.py` (블루투스 클라이언트), 공통 `motors.py`, `sensors.py`, `guards.py`.
- 허브 주소, 계정, 비밀번호는 브릭 로컬 설정에서 읽고 코드에 직접 쓰지 않음.

### 5B.4 브릭 내 안전 장치 (네트워크를 거치지 않음)

허브가 **어떤** 종류든 안전 판단은 브릭에서 합니다.

- **센서 가드:** 원점 복귀 중이 아닐 때 설정된 센서가 감지되면 그 브릭의 모든 모터 정지, 잠금, 이벤트 전송. 마스터가 다른 브릭에도 정지 전달.
- **원점 복귀 가드:** 원점 복귀 명령에 `{sensor, motor}`가 함께 오고, 그 센서가 그 모터를 멈춤 (원점 복귀 완료이며 오류 아님).
- **정지 감지 가드:** 명령 중인 모터 속도가 300ms 넘게 거의 0이면 정지하고 보고.
- **모터 각도 제한:** `set_guards`로 받은 포트별 최소·최대값 (숫자만).
- **하트비트 워치독:** 2초간 하트비트 없으면 전체 정지. 모바일 허브가 백그라운드로 가거나 화면이 잠기는 경우도 여기서 처리. **블루투스 워치독:** 슬레이브가 마스터와 끊기면 슬레이브 전체 정지.
- **잠금:** `clear_latch` 전까지 이동 명령 거부.

### 5B.5 PC 드라이버 (PC Transport 어댑터) · `src/adapters/pc/mqtt_transport.py`

- 컨트롤러 패키지의 **Transport** 인터페이스를 PC용으로 구현: `send(brick, cmd)`, `on_state(cb)`, `on_event(cb)`, `estop()`, 하트비트 스레드.
- 도구와 확인용 편의 함수: `move_motors({(brick, port): angle}, speed)`, `read_state()`, `stop()`, `home_motor(...)`, `set_guards(...)`.
- 어떤 PC 스크립트에서든 키보드 비상 정지.
- 로봇 정보를 갖지 않음. 코어 로직(5C단계)은 Transport 인터페이스를 통해서만 사용.

### 5B.6 연결 확인 · `src/ev3/check.py`

- 두 브릭에 ping, `info` 출력 (모터 6개, 센서 5개 확인).
- 모터마다 저속 ±10° 조그, 값 확인, 브릭별 왕복 지연 (마스터, 슬레이브 따로).
- 센서 값 실시간 출력, 터치 센서를 눌러 이벤트 확인.
- **브릭 간 지연:** 한 브릭의 센서가 다른 브릭의 모터를 멈출 때까지 걸리는 시간 (J4 원점 복귀에 필요). 기록.

## 안전

- 속도 상한 100°/s, ±10° 조그만 (이 단계에서는 관절 범위를 모름).
- 각 모터를 처음 움직일 때 손으로 팔을 받쳐 둡니다.

## 완료 기준

- [ ] 두 브릭 온라인, `info`에 모터 6개와 센서 5개가 모두 나옴.
- [ ] 모든 모터가 조그되고 ±3° 안에서 값이 읽힘, 브릭별 지연 기록.
- [ ] 조그 중 터치 센서를 누르면 같은 브릭은 50ms, 다른 브릭은 300ms 안에 정지 (브릭 간 지연 기록).
- [ ] `robot/estop`으로 두 브릭이 300ms 안에 정지.
- [ ] 허브 프로세스를 종료하면 두 브릭 정지 (하트비트 워치독).
- [ ] 블루투스를 끊으면 슬레이브 정지.
- [ ] `set_guards`의 모터 각도 제한이 범위 밖 목표를 거부.
- [ ] **오프라인 시험:** 공유기의 인터넷(WAN)을 끊은 상태에서 연결 확인 전체 통과.
- [ ] 익명 MQTT 접속 거부, `hub`가 아닌 계정은 권한 설정으로 `robot/cmd/#` 발행 차단.
- [ ] 공유기 포트 포워딩 없음, 방화벽이 1883 포트를 로컬망 대역으로 제한.
- [ ] 브릭 설정의 `hub_address`만 바꿔도(예: 같은 브로커 설정을 쓰는 로컬망의 다른 기기) 코드 수정 없이 다시 연결됨.

## 대안

Day 4가 끝날 때까지 브릭의 MQTT가 불안정하면 같은 메시지 형식을 마스터의 일반 TCP 소켓으로 주고받습니다. 브릭 간 블루투스가 불안정하면 슬레이브도 Wi-Fi에 연결해 직접 구독합니다.
